# Harness: antigravity

> Moved from `CLAUDE.md`, where this was the `antigravity` bullet of “Agent command shape”. Index of all subsystem docs: the [Topic map in CLAUDE.md](../../CLAUDE.md#topic-map).

**`antigravity`** → driven through `src/bun/antigravity-tmux.ts` (Google's Antigravity CLI, binary `agy`; structurally a near-clone of the gemini/codex one-shot drivers).
Each turn is a one-shot `agy --output-format stream-json --model <id> [--dangerously-skip-permissions | --mode plan | --mode accept-edits] [--conversation <id>] -p` hosted **inside a detached per-task tmux session** (`-x 200 -y 50`) so a mid-turn run survives an agetor restart.
The prompt is a positional argv element read from the per-run prompt file — `sh -c '"$@" "$(cat <promptfile>)" > <runlog> 2>&1; echo $? > <exitfile>' sh <argv…>` — so it never enters shell text and has no argv-size cap of its own to enforce, and the exit code lands in a sibling file (`readAntigravityExitCode`).
Structured output comes from tailing the stream-json NDJSON log (`dataDir/antigravity-logs/<runId>.jsonl`); `mapAntigravityEvent` maps `init` (conversation id), `step_update` (an `agent_response` `text_delta` stream coalesced per `step_index` by `AntigravityTextCoalescer` into one `assistant` chunk keyed `antigravity:step_<index>` on `DONE`/boundary/settlement so Markdown stays intact; a `tool` step `ACTIVE` → `tool_use`, `DONE` → `tool_result`, `ERROR`/`FAILED`/`CANCELLED` → `tool_result` with `isError: true`, keyed `step_<index>`), `result` (`SUCCESS` → done, anything else resolves failed with its `stderr`; the `response` text is used only when no delta text was emitted) and `error`, with line uuids `antigravity:step_<index>` / `antigravity:<n>` / `antigravity:result:<n>`.
The `init` event's `conversation_id` is persisted as `runs.antigravity_session_id` (migration 061) and replayed via `--conversation <id>` on follow-up turns — continuity lives in the id, not a live REPL — and boot reconciliation reattaches through `reattachAntigravitySession` only WHILE a turn is in flight (same rule as codex/gemini); the death watch emits the shared `SESSION_DIED_STATUS_PREFIX` sentinel.

**Modes**: `auto` → `--dangerously-skip-permissions`, `plan` → `--mode plan`, `ask` → `--mode accept-edits` (labelled "Accept edits").

**Effort lives in the model id suffix, not a flag (grouped like Cursor)**: `agy models` lists flat suffixed variants (`gemini-4-neon-high`, `gemini-4-neon-xhigh`, `gemini-4-argon-high`, `gemini-3.8-flash-high`, `claude-opus-5-5-high`, `gpt-oss-120b-medium`, …) alongside effort-less rows (`gemini-pro-orchestrator*`). `parseAntigravityModelList` (`src/shared/antigravity-catalog.ts`) collapses `<base>-<effort>` families into one picker row per base model (`Gemini 4 Neon`, `Gemini 4 Argon`, `Gemini 3.8 Flash`, …) with their effort ladders (`efforts` + `antigravity.effortIds`), while effort-less models stay plain rows with no effort picker. The 7 curated fallback specs in `ANTIGRAVITY_MODEL_SPECS` (Gemini 4 Argon, Gemini 3.8 Flash [default + `high`], 3.6 Flash, 3.1 Pro, Claude Opus 5.5, Sonnet 5.5, GPT-OSS 120B) mirror the same base + effort shape; `buildCommand` composes `(model, effort)` back to `--model <variant>` via `antigravityModelArg` (never emitting `--effort`, and passing flat legacy ids or effort-less ids verbatim). Migration 094 normalizes older stored flat `<base>-<effort>` antigravity tasks, profiles, and `lastModel:antigravity` / `lastEffort:antigravity` preferences into base + effort, and `model-discovery.ts` normalizes any pre-existing flat `modelCatalog:kind:antigravity` cache on hydration.
Antigravity is NOT in `CATALOG_SCOPED_KINDS`, so `agy models` discovery leads in CLI order and curated rows the CLI did not list follow (`mergeModelOptions` rule 4).
Migrations 064/065/066/094 are all kind-joined on `harnesses.kind`, because ids like `gemini-4-argon-*` and `gemini-3.7-flash*` are shared with Cursor.
An additional-account harness isolates via a full `HOME` override (cursor/fx-style).
Install is `brew install --cask antigravity-cli`; upgrade is `agy update` (or `brew upgrade antigravity-cli` for a Homebrew install); the version probe is `agy --version`.

**No usage-limit or quota checks, ever.** Google has reported that requests for an Antigravity account's usage limits made outside its own services can get the account flagged or banned. So agetor never polls, probes or parses quota for antigravity: the kind is not in `USAGE_SUPPORTED_KINDS` (no usage poller provider, no usage chip), not in `HARNESS_STACK_KINDS` (no limit classifier, cooldown or limit retry), and no source file calls a Cloud Code quota endpoint. agetor reaches Antigravity only through the `agy` binary (a turn, `agy models`, `agy --version`). `src/bun/antigravity-no-usage-checks.test.ts` pins all of it.

`agy models` is never run unattended: the boot sweep and the 15-minute periodic sweep skip it (`refreshAllModels` passes `background: true` to `refreshDiscoveredModels`, which hands `discoverAntigravity` a `skip`; the flag is carried apart from `kindTargets`, so a failed target resolution cannot drop it), because the model list may come from the same backend call quota tools read. It runs only on a manual refresh (`POST /agent-models`, which calls `refreshAllModels({ manual: true })`), a per-harness refresh (`POST /agent-models?harness=`), or a harness status change (install, CLI version, login), all through `refreshHarnessModels`. Between those the held catalog stays (an empty skipped probe keeps it, per `settleCatalog`; a CLI version change drops it), and on a first launch with no stored catalog the picker shows the curated rows until one of those triggers runs. Pinned by the antigravity test in `model-discovery.test.ts`.

**Unlike codex/cursor/gemini/fx/opencode (which ship disabled — but see the auto-enable rule in [harnesses.md](harnesses.md)), migration 061 seeds the built-in `antigravity` row `enabled = 1` on purpose** — and migration 077 later seeded `copilot` enabled the same way.
Env seams: `AGETOR_ANTIGRAVITY_BIN`, `AGETOR_ANTIGRAVITY_ARGS` (spliced before the trailing `-p`) and `AGETOR_ANTIGRAVITY_DRIVER=fake`.
