# Agents + Pipelines bundle (export/import)

> Moved from `CLAUDE.md`, where this was orchestration-flow item 20. Index of all subsystem docs: the [Topic map in CLAUDE.md](../../CLAUDE.md#topic-map).

**Agents + Pipelines bundle** (export/import; `docs/plans/agents-pipelines-import-export.md`, grill `docs/plans/agents-pipelines-import-export-grill.md`): one versioned, pretty-printed JSON file — `{format: "agetor-bundle", version: 1, exportedAt, agetorVersion, agents[], pipelines[]}`, 2-space indent + trailing newline (`serializeBundle`) — carries any selection of Agents and Pipelines.

**Format** (`src/shared/bundle.ts`, zero runtime imports outside `src/shared/`): each Agent carries `key` (file-local, slugged from its name, `agent-<n>` fallback, `-2`/`-3` on a clash — never stored), `name`, `harness: {id, kind, label}` (`kind` is the built-in harness an additional-account harness such as `secondary-claude-code` wraps
— the "original harness" an import falls back to; harness `home`/`bin`/`env` are never written and never read), `model/effort/mode/speed/fast/maxMode/instructions/skills` (`speed` is the tier; `fast` is written as `speed !== "off"` so an older agetor still imports the Agent — Ultrafast as Fast; the parser accepts `speed` (a strict enum
— anything else is a field error naming off, fast, ultrafast) and/or `fast` (boolean), `speed` wins, and the format stays version 1); a Pipeline carries `name/description/maxSteps/graph` with steps referencing Agents by key (`agent`, `subagents.agents`) — the parser maps those onto `agentProfileId`/`subagents.profileIds` and runs the ordinary `validatePipelineGraph`.
`buildBundle` embeds every Agent a selected Pipeline references (steps, then delegations) once, after the selected Agents in name order; a step whose Agent is gone exports `agent: null` and an Agent whose harness no longer resolves — or that has no model while its harness kind has no `DEFAULT_MODEL` (a row left by a retired kind) — is skipped, both with export-time warnings that name the skip reason (the step and delegation warnings reuse it per Agent id).

**Every export imports** (plan K11b): the local write paths are looser than the parser (an ANSI escape pasted into instructions or a pipeline description is stored, a harness label is uncapped), so `buildBundle` removes lone surrogates (a JSON column or route keeps `"\ud800"`, and the parser refuses one in every field;
in step names, step instructions and edge labels it replaces them with U+FFFD instead, as `String.prototype.toWellFormed` does, since removing one could empty a name and the validator would refuse the whole Pipeline — "replaced with U+FFFD" in the warning; every lone surrogate becomes the same U+FFFD, so `keepReplacedTextDistinct` then gives a replaced step name that now clashes
— with another name, or with an unchanged label on a sibling edge of a step that leads to it — a ` 2`/` 3` suffix (an unchanged name keeps it) and removes a replaced edge label that now equals another label of its step or a sibling target's name), terminal escape sequences whole (`ANSI_ESCAPE_G` — CSI, OSC/DCS strings only with their terminator and only within one line (an unterminated one, or one whose body would cross a line break, keeps the text after it
— losing lines of instructions is worse than `]0;title` residue), `ESC` + intermediates whose first isn't a space, `ESC 0-?` and `ESC c` — never `ESC` + an arbitrary letter nor `ESC` + space + letter, so no `[31m` residue and no eaten word) and then the control and invisible characters the parser refuses (step names and edge labels included), cuts a single-line field over its parser cap (harness label/model 200, effort/mode 100;
surrogate-safe), exports a model that cleaning empties as the harness kind's `DEFAULT_MODEL` (with a warning), numbers an Agent or Pipeline whose name cleaning empties `Agent N`/`Pipeline N` (`fillEmptyNames`: N counts up from its position past any name the file already holds under `bundleNameKey` — the planner's name key, defined in `bundle.ts` and imported by `bundle-import.ts`
— so it never collides with a real "Pipeline 2" and gets renamed silently on import; "given a numbered one" in the warning), keeps Agent and Pipeline names cleaning made equal apart (`keepNamesDistinct`: two local names that differed only by an invisible character — `Reviewer` and `Reviewer\u200b` — would otherwise both export as `Reviewer` and import as an unexplained `(imported)`;
names cleaning left alone reserve theirs first, a later clash under `bundleNameKey` takes a ` 2`/` 3` suffix within the cap, "renamed to keep them distinct" in the warning), cleans step ids, edge ids and Agent references import refuses (`cleanStoredGraph` via `cleanId`: control characters, lone surrogates and
— by the single-line rule — C1 controls, bidi overrides and every other invisible character removed, ids kept unique with a `-2` suffix, edges and `startStepId` remapped, a graph whose ids already repeat left for the validator to refuse; a cleaned reference names no stored Agent, so its step exports without it), keeps step names valid (one stripping empties becomes `Step N`, of two stripping makes equal
— `Review` and `Review\u200b` — the one cleaning changed gets a ` 2`/` 3` suffix within the 60-char cap whatever the step order (an unchanged name keeps it, so a `next` naming it still routes there) — as does a changed name that meets an unchanged label on another edge out of a step leading to it, or the id of another target of such a step (`resolveNextSteps` tries names before ids), "renamed to keep them distinct" in the warning;
"changed"/"unchanged" compare `stepNameKey`s, so a label stored as `Yes ` that exports trimmed still counts as unchanged), drops an edge label cleaning changed that it makes equal to another outgoing label of the same step or to a sibling target's (cleaned, maybe renamed) name (labels cleaning left alone are kept first, whatever the edge order, so a `next` naming one still routes where it did;
the edge still routes; "removed" in the warning), with one warning per Agent/Pipeline naming the fields and using its cleaned name — runs each selected Pipeline's stored graph through `validatePipelineGraph` first and exports the normalized result (`parsePipelineGraph` hands back a shape-safe graph today's validator refuses as-is
— a legacy or hand-edited row, an edge with no `label` — which is refused by Pipeline name, "fix it in the pipeline editor", instead of crashing the export), refuses more than 500 Agents / 200 Pipelines, and round-trips its own text through `parseBundleText`, refusing an export over 2 MB ("export fewer at a time") or one failing any other rule (the message names the Agent by display name, not file key);
`POST`/`PATCH /agent-profiles` cap `model` (200) and `effort`/`mode` (100) to match (`AGENT_PROFILE_LIMITS`) and refuse a `model` carrying a control or invisible character (`agentProfileModelError`), a lone surrogate in `name`/`model`/`effort`/`mode`/`instructions`/`skills` (`loneSurrogateError`; `POST`/`PATCH /pipelines` refuse one in `name`/`description`), storing `effort`/`mode` trimmed with a blank one as `null`
— the same reading the parser applies; the routes answer 400 and nothing is written, while the parser itself stays strict (a bundle is third-party content).
File name: `<slug>.agetor.json` for one selected item (slugged from its cleaned name, so an escape sequence's bytes never reach it), else `agetor-export-YYYY-MM-DD.agetor.json` (the local date, `localDate`).
`parseBundleText` (2 MB UTF-8 cap `BUNDLE_MAX_BYTES`, ≤500 Agents/≤200 Pipelines `BUNDLE_LIMITS`, every `AGENT_PROFILE_LIMITS`/`PIPELINE_LIMITS` cap, C0/DEL refused in identifiers and only `\t\n\r` allowed in multi-line text, step/edge ids and Agent references (`agentProfileId`, `subagents.profileIds`) refused by `validatePipelineGraph` itself when they carry a C0 control character or lone surrogate (`LONE_SURROGATE_RE` now lives in `src/shared/pipeline.ts`, re-exported by `bundle.ts`;
the validator also refuses one in step names, instructions and edge labels, so `POST`/`PATCH /pipelines` do too — retroactively: `startPipelineRun` re-validates the stored graph (and a restart's frozen snapshot fallback), so a pipeline stored earlier with a lone surrogate there refuses to start with "pipeline graph is invalid" until that text is edited) and by `checkGraphText` when they carry an invisible character (C1, a bidi override, a zero-width or tag character, the BOM
— import keeps ids verbatim) — a legacy file's reference nothing local matches is stored as it was and printed by `agetor pipeline show`, whose `profileText` escapes it anyway, a lone UTF-16 surrogate refused in every text field and in a typed import name (`LONE_SURROGATE_RE` — JSON can spell one, and SQLite would store `Review\ud800er` as `Review𐁥r`, a name other than the previewed one), invisible characters refused too since no preview can show them (`findInvisibleChar`, naming the code point: every `Default_Ignorable_Code_Point`
— zero-width characters, word joiners/invisible operators, U+206A–206F, bidi overrides/isolates, the BOM, Hangul fillers, variation selectors, the whole U+E0000–E0FFF tag block, which can spell out an instruction a model reads — plus C1, interlinear annotations and (single-line only) line/paragraph separators, minus a context-bound allowlist
— each allowed character only right after a visible one (never two in a row) and only where real text needs it, so no free position is left to hide bits in (one selector interleaved after every letter, or a ZWJ/ZWNJ binary run, used to carry bytes): U+FE0E/FE0F only after an emoji (`\p{Extended_Pictographic}`) or a keycap base 0-9/#/* followed by U+20E3, Mongolian U+180B–180D/180F only after a Mongolian letter, ZWJ only between an emoji (or its skin-tone modifier or U+FE0F) and the emoji it joins, and
— multi-line text only — ZWJ/ZWNJ between two letters/marks of an Arabic-family joining or Indic script (`JOINING_SCRIPT_RE`, by script extension) and CGJ between a letter/mark and a combining mark; the soft hyphen, LRM/RLM/ALM and the variation selectors U+FE00–FE0D/U+E0100–E01EF are refused everywhere (a model reads the same text without them;
one supplement selector after each ideograph used to carry a byte a character); the export stripping (`stripInvisible`, repeated to a fixpoint since removing one character can leave its neighbour out of context) and `escapeControlChars` share the same rule, so `Reviewer\u200b` can't import beside a local `Reviewer`;
emoji subdivision flags and ideographic variation sequences are the accepted casualties), unknown keys ignored — except a step's internal `agentProfileId` or `subagents.profileIds` when non-empty, which are refused ("not a bundle field") rather than dropped, since dropping them would lose the step's Agent or delegations without a word (likewise a step's `subagents` that is present but neither null nor an object
— `["r"]`, a string, a number — in bundle and legacy files alike, which the graph validator would otherwise read as no delegations; and, in both file kinds, a step's non-string `instructions`, an edge's non-string `label` — both of which the validator would read as `""` — and a second edge between the same two steps, which it would collapse into the first and lose its id and label (`refuseCoercedGraphFields`, which leaves a repeated edge that is broken anyway
— a self-edge, an end naming no step, any edge of a graph whose step ids repeat — to the validator, so the message names the real problem)) — `version > 1` → "update agetor to import this file") never throws and returns `{ok:false, error, code: "too-large"|"invalid-json"|"unrecognized"|"unsupported-version"|"invalid"}`
— `error` quotes file text, so it goes through `escapeControlChars` (C0/C1/DEL, bidi overrides and every single-line invisible character written as `\uXXXX`, astral ones as `\u{XXXXX}`; exported for the CLI — the text-safety helpers (`escapeControlChars`, `escapeFreeText`, `escapeCapped`, `findInvisibleChar`, `stripInvisible`, and `truncateText`, the surrogate-safe display cut `agetor ls`/`show` and the TUI use before escaping) live in `src/shared/terminal-text.ts` and are re-exported from `bundle.ts`;
non-bundle CLI code imports them from `terminal-text.ts`) and is capped at 500 characters (`escapeCapped` cuts the raw text before escaping, so a `\uXXXX` is never split): `agetor import` prints it to a terminal, where a raw ESC would be the file author's escape sequence; a JSON object with no `format`, a string `name` and an object `graph` is a **legacy** pre-bundle pipeline file (`legacy: true`, its per-step `profileName`/`subagents.profileNames` hints kept as `legacyHints`
— a hint over `LEGACY_HINT_MAX` (4 × the 80-char Agent name cap) is dropped, since it can't name a stored Agent, and warnings quote a hint cut to 60 characters).

**Planner** (`src/shared/bundle-import.ts`, `planBundleImport` — pure, total, run by the server for the preview AND again inside the commit transaction; every plan carries a `fingerprint` (`planFingerprint`, a cyrb53 hash of each Agent's final name/harness/launch fields (`speed` included), each Pipeline's final name and step bindings (for a legacy file, also whether each step and delegation reference was kept, remapped or left dangling
— the stored id is the same either way, so an Agent deleted between preview and Confirm only shows up there), and which of its harnesses the user asked to enable — not their current state, so a harness enabled or disabled elsewhere meanwhile is not drift), and a commit sent with the previewed one 409s with the new plan when the re-plan differs
— so a name taken or a harness added between preview and Confirm can't silently change what gets created): per Agent, an override (`agentHarness[key]`, else `harnessMap[fileHarnessId]`) binds a same-kind local harness (`mapped`), blocks on another kind (`harness-kind-mismatch`) or an unknown id (`unknown-local-harness`), and re-binds an Agent of a kind this build doesn't know to ANY local harness with model reset to `DEFAULT_MODEL[kind]`, effort/mode `null`, speed `off`, maxMode `false` (`rebound`, warning `settings-reset`);
with no override, a local harness with the file's id AND kind binds silently (`exact`), else the built-in of the file's kind (`fallback`, warning `harness-fallback`), else an unknown kind is `unresolved` and blocking (`unknown-kind`) until mapped.
A local harness whose own kind this build can't run (a retired kind the `harnesses.kind` CHECK still admits) is never a candidate, and an override naming one blocks (`unsupported-local-harness`) — it has no `DEFAULT_MODEL` to reset to.
Labels never match.
Target-harness status adds warnings only (`harness-disabled` unless `enableHarnesses` lists it or is `"all"`, `harness-not-installed`, `harness-logged-out`); model (`unknown-model`: discovered catalog ∪ non-`catalogOnly` curated rows, all curated rows while discovery is empty, only the non-gated curated rows for a logged-out harness (`mergeModelOptions` rule 7); skipped for `rebound`) and user-level skill (`unknown-skills`, claude-code/codex only) warnings never block.
Names: a clashing name (by `nameKey` — built on the stored `name_key` (`trim().toLowerCase()` first: lower-casing and NFC don't commute, and NFC-first let `J`+U+030C preview as free beside a local `j`+U+030C that every commit then 409ed), then NFC-normalized, `Default_Ignorable_Code_Point`s removed, whitespace runs (Braille blank U+2800 included) folded to one space, trimmed, case-insensitive
— so a lookalike that only differs by an invisible character or by composition clashes too; against local rows and earlier items of the same file) becomes `Name (imported)`, `Name (imported 2)`, … truncated to 80 (`importedName`, surrogate-safe, and a joiner/selector the cut strands — a ZWJ whose emoji was cut off
— is dropped so the name still imports); an explicitly typed name (`agentNames[key]`, `pipelineNames[index]`, or CLI `--name` = `singleName`, which renames the only Pipeline, else the only Agent of a Pipelines-less file, else blocks `name-not-applicable`) must be free — a clash blocks (`name-in-use`), never suffixes.
Legacy files keep the old rule: a local id is kept, else a unique case-insensitive name match is used, else the reference dangles with a warning.

**Server** (`src/bun/bundle.ts`; thin routes in `server.ts`, all `authed`): `POST /bundle/export` (`{agentIds?, pipelineIds?, all?}` → `{text, filename, warnings, counts}`; 400 on an empty selection, `all` mixed with ids, an unknown id, or an export import would refuse), `POST /bundle/export/save` (+`target: "downloads"|"folder"` → `{path, filename, revealed, warnings, counts}` or `{cancelled: true}`;
Downloads = `AGETOR_DOWNLOADS_DIR` when set (test seam) else `~/Downloads` (created when missing), then `native.revealPath` — headless writes anyway with `revealed: false`; folder = the fake-pick seam dir, else the native panel in folder mode, else 501 — a picked folder must already exist (never created), and both native-panel routes re-join the pick with `singlePickedPath` (`src/bun/native-pick.ts`, which `/projects/pick` now uses too, and whose multi-selection sibling `pickedPaths`
— a non-absolute piece joins the path before it, an absolute one too when the join exists and one of the two halves doesn't (or both exist but the second isn't inside the first's folder, as `/Library` beside `/d/Backups` isn't), across any number of folders whose names end in `,` (the run grows only while the next join's parent folder exists)
— backs `/refs/pick`, whose `refsFromPaths` never trims a path) because Electrobun's `openFileDialog` splits its answer on `,` (a `Backups, 2026` folder arrives in pieces) — never trimmed (a folder name may end in a space), a relative answer reads as cancelled; the export is built before the folder panel opens (a selection that can't export fails first) and again after the pick, so the file holds what exists at save time;
files are created `wx` and numbered `name (2).agetor.json` … up to 999, never overwritten; 500 on a write failure — `bundleSaveErrorMessage` turns EPERM/EACCES, almost always macOS Files and Folders privacy, into a hint naming the System Settings pane and the alternatives instead of a bare errno, and EEXIST/ENOTDIR from creating Downloads into "exists but isn't a folder"), `POST /bundle/pick-file` (`{text, filename}` | `{cancelled: true}`;
the native panel with `allowedFileTypes: "json"` — `ApiNative.openFileDialog` grew that optional field and `index.ts` only forwards it when set, since Electrobun spreads options over its `"*"` default — or the first `*.json` in the fake-pick seam dir; 400 over 2 MB; 501 headless), `POST /bundle/import/preview` and `POST /bundle/import` (`{text, options?, planFingerprint?}`;
option maps are built with `Object.fromEntries` so a `__proto__` Agent key or harness id survives (an assignment would hit the prototype setter), and the webview's preview reads them through `ownOption` (`Object.hasOwn`), since an Agent named "Constructor" exports with the key `constructor` and a plain index would read `Object.prototype` (legacy step hints are built and read the same way);
a body over `BUNDLE_MAX_REQUEST_BYTES` = 2 × 2 MB + 64 KB (defined in `src/shared/bundle.ts` so the webview checks a request against it too, re-exported by `src/bun/bundle.ts`) is refused 413 by `Content-Length` before parsing, and a chunked one (no length) as soon as the capped read (`readBodyCapped`) passes it
— either way `drainRefusedBody` then reads and drops the rest of the upload (≤64 MB, and for at most 5 s — a stalled or trickling upload is cancelled at the deadline so it can't hold the 413 back) rather than leaving it on the socket, since Bun's keep-alive fetch otherwise wedges its next request behind it and a `Connection: close` response header doesn't help (spike-verified, Bun 1.3.10);
a give-up (`reader.cancel()`) still sacrifices that socket until the 255 s `idleTimeout`, so `Bun.serve` sets `maxRequestBodySize` to the same 64 MB (`REFUSED_BODY_DRAIN_MAX_BYTES`; the largest legitimate body, `POST /screenshots`, is 25 MB) — Bun refuses a larger Content-Length body itself with a clean socket, but (spike-verified, 1.3.10) does not apply that limit to a chunked body, so only a chunked body over 64 MB or a client that stalls mid-upload reaches the cancel, neither of which the webview or CLI sends;
the 413 says the request (not the file) is too large, because text full of control characters grows up to 6x as JSON; 400 `{error, code}` for a file that doesn't parse; import answers 201 `{agents, pipelines, enabledHarnesses, warnings, plan}` or 409 `{error, plan}` when blocked or when `planFingerprint` no longer matches
— "the import changed since the preview"; without it (an older client) the re-plan is trusted).
The native-panel routes call `server.timeout(req, 0)`.
Nothing reads or writes a client-supplied path.
`gatherBundleLocalState` lists every harness (adding a synthetic built-in for a kind with no row, mirroring `harnesses.getByIdOrKind`) and probes status + user-level skills only for harnesses of the file's kinds (all of them when a kind is unknown), cached 5 s across previews.
`commitBundleImport` probes first, then inside ONE `db.transaction` re-reads names/harness rows, re-plans, throws if blocked, enables the chosen disabled harnesses (`harnesses.setEnabled`), inserts Agents through the unchanged `agentProfiles.insert` (key → new id), rewrites each graph's keys to ids and inserts Pipelines through `pipelines.insert` — any throw rolls everything back (500 "nothing was imported"); a name race surfaces as 409; after commit `refreshHarnessModels` fires for each enabled harness.

**Human steps: conditional version 2.** A bundle that carries no human step is still written as `version: 1` and is byte-identical to a pre-human-step export (no `type` key anywhere). A bundle containing a human step is written as `version: 2`, with `type: "human"` on that step only (agent steps still omit `type`). `parseBundleText` accepts versions 1 and 2, refuses a `type: "human"` step in a version 1 file ("a human step needs bundle version 2 — update agetor to import this file"), refuses any other `type` value, and refuses version 3+ with the existing "update agetor to import this file" copy. Old readers therefore reject a human bundle instead of running the step agent-lessly. The import planner marks a human step `type: "human"`, shows "→ Human review" in the preview, and never raises the "step has no Agent" warning for it.
