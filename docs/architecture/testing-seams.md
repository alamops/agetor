# Test seams: native pickers, downloads and the fake OpenCode server

> Moved from `CLAUDE.md`, where this was the `POST /refs/pick` bullet of “Things that will trip you up”. Index of all subsystem docs: the [Topic map in CLAUDE.md](../../CLAUDE.md#topic-map).

`POST /refs/pick` opens a native open-panel and answers "not available" in the headless backend — the Playwright harness has no native bridge.
`AGETOR_FAKE_PICK_REFS_DIR=<dir>` is the test seam (same spirit as `AGETOR_*_DRIVER=fake`, env wins whenever set): mode `files` returns that directory's immediate regular files, mode `folder` returns the directory itself, a missing dir reads as a cancelled pick.
`e2e/fixtures.ts` creates `<dataDir>/fake-picks`, sets the env and exposes it as `backend.fakePickDir` — write the files a spec wants "picked" there, then click `refs-pick-files`/`refs-pick-folder` — always scoped to the container (the dialog or the run panel): the New Task panel's expandable picker and RunPanel's inline picker are mounted at the same time and share the inner ids (`refs-pick-*`, `refs-chip`, `refs-remove`); only the roots are variant-specific (`refs-dropzone-expandable` / `refs-dropzone-inline`).
Drops are drivable without a seam (a `text/uri-list` of `file://` URLs dispatched on `refs-dropzone`), but `capture-refs.ts`'s `isTransientPath` filters `/tmp` and `/var/folders`, so a dropped fixture file must live outside the temp dirs (the repo checkout works).
The [bundle](bundle.md) routes reuse the same seam — `/bundle/export/save` with `target: "folder"` writes into that directory and `/bundle/pick-file` returns its first `*.json` file (name order) — and add `AGETOR_DOWNLOADS_DIR=<dir>` for Save to Downloads (`e2e/fixtures.ts` points it at `<dataDir>/fake-downloads`, exposed as `backend.downloadsDir`).
A bundle drop needs no seam: the drop handler reads the dropped `File` with `File.text()`.

**The fake OpenCode server.** The OpenCode 2.x server driver ([harness-opencode.md](harness-opencode.md)) is tested against `src/bun/fixtures/opencode/fake-serve.ts`, a Bun implementation of the `/api` subset it uses (Basic auth, a global SSE stream, sessions in memory), started by a stub `opencode` binary (`stub-opencode.sh`, set as `AGETOR_OPENCODE_BIN`) whose `serve` subcommand execs it.
Unlike the seams above this one exercises the real driver, hub and server manager end to end; only the OpenCode binary is faked.
The scenario is chosen by a marker in the prompt: `__agetor_fake_oc_steer__`, `_permission__`, `_question__`, `_subagent__`, `_wake__`, `_error__`, `_slow__`, `_stuck__` (the interrupt answers `{interrupted:true}` and nothing ends, for the unconfirmed-Stop path), `_bgslow__` (a background child and its parent both busy until interrupted), `_todo__`, `_retry__`, `_files__`, `_tool__`.
Its knobs are `FAKE_OC_SPEED`, `FAKE_OC_HEARTBEAT_MS`, `FAKE_OC_STATE_FILE`, `FAKE_OC_QUOTA_MODELS`, `FAKE_OC_VERSION`, `FAKE_OC_INTERRUPT_DELAY_MS` (a delay before the interrupt route acts and answers; above the client's interrupt timeout the call itself times out) and `FAKE_OC_BUN`, all documented in the file's header (`FAKE_OC_BUN` in `stub-opencode.sh`).
It models the inbox the r3 spike recorded (`docs/plans/opencode-server-driver-spikes.md`): an item enqueued on an idle session starts an execution, an item still undelivered when an execution ends `interrupted` stays parked with no event until the next execution delivers it first, `GET …/inbox` lists the undelivered items and `DELETE …/inbox/{id}` cancels one (204 with one `session.inbox.cancelled`, or 204 and no event for an unknown, delivered or already cancelled id).
`AGETOR_OPENCODE_SERVER_HOST=direct` hosts the server as a `coreSpawn` child of the core instead of in tmux, so unit and e2e runs need no tmux; it is test-only and nothing in a release flow sets it. It is honored only under `NODE_ENV=test` (every `bun test` run) or `AGETOR_E2E_OPENCODE_DIRECT_HOST=1`, which the e2e backend sets because it does not run under `NODE_ENV=test`; elsewhere it is ignored.
`AGETOR_OPENCODE_TRANSPORT=run` forces the legacy `opencode run` driver, and `AGETOR_OPENCODE_DRIVER=fake` keeps its canned-NDJSON path.
A test that runs the real driver must restore every one of these env vars, since `bun test` shares one process, and should set `FAKE_OC_HEARTBEAT_MS` well under the driver's 45 s stall watchdog (about 2 s) and wait on events rather than sleeping to prove something did not happen.
