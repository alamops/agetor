# Test seams: native pickers, downloads, the fake OpenCode server, the harness-stack retry floor and its mirror/sweep pauses

> Moved from `CLAUDE.md`, where this was the `POST /refs/pick` bullet of “Things that will trip you up”. Index of all subsystem docs: the [Topic map in CLAUDE.md](../../CLAUDE.md#topic-map).

`POST /refs/pick` opens a native open-panel and answers "not available" in the headless backend — the Playwright harness has no native bridge.
`AGETOR_FAKE_PICK_REFS_DIR=<dir>` is the test seam (same spirit as `AGETOR_*_DRIVER=fake`, env wins whenever set): mode `files` returns that directory's immediate regular files, mode `folder` returns the directory itself, a missing dir reads as a cancelled pick.
`e2e/fixtures.ts` creates `<dataDir>/fake-picks`, sets the env and exposes it as `backend.fakePickDir` — write the files a spec wants "picked" there, then click `refs-pick-files`/`refs-pick-folder` — always scoped to the container (the dialog or the run panel): the New Task panel's expandable picker and RunPanel's inline picker are mounted at the same time and share the inner ids (`refs-pick-*`, `refs-chip`, `refs-remove`); only the roots are variant-specific (`refs-dropzone-expandable` / `refs-dropzone-inline`).
Drops are drivable without a seam (a `text/uri-list` of `file://` URLs dispatched on `refs-dropzone`), but `capture-refs.ts`'s `isTransientPath` filters `/tmp` and `/var/folders`, so a dropped fixture file must live outside the temp dirs (the repo checkout works).
The [bundle](bundle.md) routes reuse the same seam — `/bundle/export/save` with `target: "folder"` writes into that directory and `/bundle/pick-file` returns its first `*.json` file (name order) — and add `AGETOR_DOWNLOADS_DIR=<dir>` for Save to Downloads (`e2e/fixtures.ts` points it at `<dataDir>/fake-downloads`, exposed as `backend.downloadsDir`).
A bundle drop needs no seam: the drop handler reads the dropped `File` with `File.text()`.

**The fake OpenCode server.** The OpenCode 2.x server driver ([harness-opencode.md](harness-opencode.md)) is tested against `src/bun/fixtures/opencode/fake-serve.ts`, a Bun implementation of the `/api` subset it uses (Basic auth, a global SSE stream, sessions in memory), started by a stub `opencode` binary (`stub-opencode.sh`, set as `AGETOR_OPENCODE_BIN`) whose `serve` subcommand execs it.
Unlike the seams above this one exercises the real driver, hub and server manager end to end; only the OpenCode binary is faked.
The scenario is chosen by a marker in the prompt: `__agetor_fake_oc_steer__`, `_permission__`, `_question__`, `_subagent__`, `_wake__`, `_error__`, `_slow__`, `_stuck__` (the interrupt answers `{interrupted:true}` and nothing ends, for the unconfirmed-Stop path), `_bgslow__` (a background child and its parent both busy until interrupted), `_todo__`, `_retry__`, `_files__`, `_tool__`.
Its knobs are `FAKE_OC_SPEED`, `FAKE_OC_HEARTBEAT_MS`, `FAKE_OC_STATE_FILE`, `FAKE_OC_QUOTA_MODELS`, `FAKE_OC_VERSION`, `FAKE_OC_INTERRUPT_DELAY_MS` (a delay before the interrupt route acts and answers; above the client's interrupt timeout the call itself times out) and `FAKE_OC_BUN`, all documented in the file's header (`FAKE_OC_BUN` in `stub-opencode.sh`).
It models the inbox the r3 spike recorded (`docs/plans/opencode-server-driver-spikes.md`): an item enqueued on an idle session starts an execution unless its prompt said `resume: false` (then a re-post of the same id starts it, once), an item still undelivered when an execution ends `interrupted` stays parked with no event until the next execution delivers it first, `GET …/inbox` lists the undelivered items and `DELETE …/inbox/{id}` cancels one (204 with one `session.inbox.cancelled`, or 204 and no event for an unknown, delivered or already cancelled id).
`AGETOR_OPENCODE_SERVER_HOST=direct` hosts the server as a `coreSpawn` child of the core instead of in tmux, so unit and e2e runs need no tmux; it is test-only and nothing in a release flow sets it. It is honored only under `NODE_ENV=test` (every `bun test` run) or `AGETOR_E2E_OPENCODE_DIRECT_HOST=1`, which the e2e backend sets because it does not run under `NODE_ENV=test`; elsewhere it is ignored.
`AGETOR_OPENCODE_TRANSPORT=run` forces the legacy `opencode run` driver, and `AGETOR_OPENCODE_DRIVER=fake` keeps its canned-NDJSON path.
A test that runs the real driver must restore every one of these env vars, since `bun test` shares one process, and should set `FAKE_OC_HEARTBEAT_MS` well under the driver's 45 s stall watchdog (about 2 s) and wait on events rather than sleeping to prove something did not happen.

**The harness-stack retry floor.** An all-exhausted stack waits at least 10 s (`HARNESS_STACK_RETRY_MIN_MS`) before an automatic retry, which is too slow for a test. `AGETOR_HARNESS_RETRY_MIN_MS=<ms>` lowers that floor (`retryMinMs()` in `src/bun/harness-failover.ts`, read at call time): a non-negative integer of at least 50, anything else (blank, non-numeric, below 50) is ignored and the 10 s floor applies. It is honored only when `NODE_ENV=test` (every `bun test` run) or `AGETOR_E2E_HARNESS_SEAMS=1`, which an e2e backend must set because it does not run under `NODE_ENV=test`; with neither, the variable is ignored and nothing in a release flow sets it. It lowers only the floor: the wait is still the provider's reset (or the 10-minute fallback) clamped to `[floor, 24 h]`, so a spec that wants a short countdown seeds a near reset time. A test that sets either variable must restore it, since `bun test` shares one process. The limit signals themselves come from the existing fake drivers (`__agetor_fake_claude_limit__`, `__agetor_fake_codex_limit__` and the pane and clean variants, see [harness-stacks.md](harness-stacks.md)).

**Harness-stack mirror and sweep pauses.** Unit tests that need an account delete, a transfer, an editor's rename or a crash to land at an exact point of a mirror, a sweep or a scheduled account switch use in-process seams, not env vars: `holdMirrorForTests(harnessId, point)` (`src/bun/harness-mirror.ts`; points `after-copy`, `file-copied` (reached only by a real write, never by a dry run), `primary-deletion-recheck`; one-shot, and `release()` also cancels a hold no run reached), `holdTransferForTests` and `pauseOrphanSweepForTests({ harnessId, sessionId })` (`src/bun/harness-session-transfer.ts`, the latter pausing the next sweep of that group between the removal and forgetting its records; keyed, so a sweep of another account or session never takes it; arm it after `orphanSweepsSettled()` and call `resetOrphanSweepPauseForTests()` in `afterEach`), `orphanSweepsSettled()` (waits for every sweep a transfer fires without awaiting, the failure and the superseded ones), `resetOrphanStampForTests()` (`src/bun/db.ts`; the next orphan stamp re-reads the table) and `setStaleTempAgeForTests(ms)` (`src/bun/harness-file-transfer.ts`; lowers the one-hour `.agetor-tmp-*` age, `null` restores it, and forgets which folders were swept).
The orchestrator's scheduled-switch edges have `__setScheduledSwitchHooksForTest({ afterIntent, waitingSettle, turnDrain })` (`src/bun/orchestrator.ts`, no-ops in production): `afterIntent` runs inside a switch-now move right after its intent is persisted and before the row changes accounts (a throw there is a move that failed after its first write; the state read there is what a crash would leave; it may return a promise, which the move awaits while it holds its claim, and only then), `waitingSettle` at the top of `settleWaitingScheduledSwitch`, and `turnDrain` in a done handler after the turn-end switch decision and before the follow-up drain. It returns the previous hooks for the test to restore.
`bun test` shares one process, so a test releases every hold, disarms every pause, restores the hooks and restores the temp age; `snapshotHarnessState` (`src/bun/test-harness-state.ts`) restores `harness_orphaned_copies` and `harness_mirror_sources` whole-row. Behaviour: [harness-stacks.md](harness-stacks.md).

**The claude model-discovery stub.** The e2e backend runs claude through the fake driver with `AGETOR_CLAUDE_BIN=/bin/echo`, so model discovery finds nothing. A spec that needs a CLI-reported catalog sets `backendEnv: { AGETOR_E2E_CLAUDE_STUB: "1", AGETOR_E2E_CLAUDE_MODELS_JSON: <file> }` (`e2e/claude-models.spec.ts`): `provisionBackend` then points `AGETOR_CLAUDE_BIN` at `writeClaudeStubBin` (`e2e/fixtures.ts`), which answers `--version` and the `initialize` control request of `src/bun/discovery/claude-probe.ts` with the file's `models[]` array (an unset file answers an empty list, i.e. an older CLI) plus a planted account block the backend must never keep. Unit tests for the probes plant their own stub scripts under `/tmp` (not `$TMPDIR`, which accumulates leaked dirs) and fixtures under `src/bun/fixtures/model-discovery/`; a test that seeds or probes the discovery caches ends with `__testing.resetForTests()` of `agent-discovery` (and `model-discovery`), or a stale codex catalog makes a later file's pre-flight refuse its model.

## Claude Enter-to-confirm screens

The boot poller and the card drive have no real-claude test in CI. These seams cover them:

- **Scripted tmux** (`src/bun/test-scripted-claude-tmux.ts`, not a test file). `AGETOR_TMUX_BIN` points at ONE stub per test file; each session is keyed by its tmux name, so a boot poller still unwinding from an earlier test only ever talks to its own session (a shared env var otherwise lets it type into the next test's pane). It models the add-dir select's two guard facts (keys inside 500 ms of mounting or of a refusal are refused and the footer turns "held"; Enter on "Yes" counts only straight after a counted Down), `refuseEnters` for a swallowed Enter, and the Enter-only, OAuth-code, theme-picker and raw-pane shapes. Used by `claude-tmux-boot-dialogs.test.ts`, `claude-tmux-card-drive.test.ts`, `server-tmux-prompt-answer.test.ts` and `orchestrator-claude-session-fresh.test.ts`. A test file that sets `AGETOR_TMUX_BIN` or `AGETOR_DATA_DIR` at top level restores it in `afterAll` (deleting it when it was unset), and one that inserts a task or run deletes it afterwards (the DB is one process-wide singleton). A test can change a live session's script with `patch` (`{ i }` to move to the next dialog, `{ typed }` to fill the OAuth field, `{ cfg }` to swap what is drawn).
- **Timeout seams.** `setBootTimeoutMs(ms | null)` and `setDeferredPromptTimeoutMs(ms | null)` (`claude-tmux.ts`) shorten the 30 s boot wait and one deferred-paste readiness window; both return the previous override.
- **Respawn window.** `__forTest.holdSpawnInFlight(taskId)` counts a spawn of the task as between its pre-kill and taking the session over, until the returned release runs, so a test can time a boot out inside that window.
- **Harness-stack retry hook.** `__setHarnessSwapSettleHookForTest` (`orchestrator.ts`) runs a callback at named points of a swap or retry; `"retry-after-warm"` is right after the all-exhausted retry's login warm-up, where a test presses Stop.
- **Fake pane (e2e).** Under `AGETOR_CLAUDE_DRIVER=fake`, `registerFakePromptPane(taskId, { text, onKeys })` registers a card through the real matcher chain, and `answerTmuxPromptInPane` and `sessionExists` treat the fake pane as live (the answer route then runs unchanged). The markers `__agetor_fake_claude_enter_prompt__` and `__agetor_fake_claude_paste_code__` (`agents.ts`) drive it from `task.prompt`; see [harness-claude-code.md](harness-claude-code.md#enter-to-confirm-screens-claude-21326).

## Multiple repositories in one task

A task created against two or more repositories stores `Task.repositories[]` and runs at a per-task workspace root with one linked worktree per repository. Preparation, the `Repositories:` launch block, per-repo diff/status/PR, per-repo teardown, nested worktree ids and the CLI/TUI surfaces are specified in [multi-repo-tasks.md](multi-repo-tasks.md). A single-repository task is unchanged (its one entry is derived from the scalar columns).
