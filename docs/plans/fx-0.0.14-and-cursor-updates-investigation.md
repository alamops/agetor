## 1. What we know

### 1a. fx: what changed between 0.0.10 and 0.0.14

Read from the release notes (`scratchpad/fx-src/releases.json`) and the source diff of `src/acp/*` (15 files, +8214/−908; `scratchpad/fx-src/diffs/`).

**Breaking changes that touch agetor**

1. **ACP's `code` mode is gone (0.0.14).** The modes are now `auto`, `ask` and `full-access` (`src/builtins/modes.zig:14-18`). `lookup("code")` returns null.
2. **`session/set_mode` rejects unknown ids and now saves the chosen mode to the user's profile (0.0.14).** An unknown id returns `-32602 "Unknown mode"`; before, it was ignored silently. A known id calls `saveSessionPermissionMode` (server.zig, diff lines 2841-2858), which writes `permission_mode` into `$HOME/.fx/settings.json`. That file is the profile the user's own interactive fx reads.
3. **The starting mode now follows `FX_PERMISSION_MODE` (0.0.14).** `loadStartingMode` reads the saved mode, and `loadPermissionMode` lets the env var override it (`src/core/app/app_lifecycle.zig:1556-1571`, test at :1598). Since 0.0.14, `modes.currentModeId` reports the real mode. On 0.0.10 it always read `ask`.
4. **Profile MCP servers are opt-in for ACP (0.0.13).** By default an ACP session loads only the servers the client sends plus approved project servers. The profile's servers (`$HOME/.fx` MCP config) load only when `session/new`, `session/load` or `session/resume` carry `_meta.fx.profileMcpServers: true` (`sessions.zig` diff 1095-1130, `appendProfileMcpConfigsIfRequested`). agetor sends `mcpServers: []` and no `_meta` (`src/bun/fx-acp.ts:2549`, `:2583`, resume at `:2491`). So with 0.0.13 or later, an agetor fx task silently loses the user's profile MCP servers. It had them through 0.0.12.
5. **Transient failures no longer pause the turn (0.0.11).** In `model_response_recovery.zig decide()`, running out of attempts used to pause the turn. Now it keeps retrying: "The turn never dies from transient failure". After 15 minutes of recovery, billable retries slow to one a minute. Connection loss waits on liveness probes instead of spending attempts. `request_limit_reached` and stalled streams **stop**; they no longer pause. `/continue` was removed from the TUI. `continueRecovery` over ACP still exists (`src/acp/prompt.zig:1696`, error text at `:1005`). In practice, the free-tier 429 storm that ended in `paused` + `refused` on 0.0.10 now keeps retrying. agetor's auto-resume engine (pause → refused → timer → `continueRecovery`) will rarely fire for that case.
6. **The recovery channel has a new `"failed"` state (0.0.14).** `writeModelRecoveryInfoUpdate` writes `"paused"` only when `action == .paused`. Any other terminal provider error writes `"failed"` (`src/acp/types.zig:52-61`). agetor's parser treats every state outside `active|paused|recovered` as **`"active"`** (`src/shared/fx-recovery.ts:92-94`). A terminal failure would therefore show as an in-progress retry, `agetor logs` would print it as a yellow progress line, and the transcript would get no summary line.
7. **`usage_update` no longer carries `cost` (0.0.14):** `writeUsageUpdate(used, size)` (types.zig diff). The RunPanel chip already treats cost as optional. Only comments and docs that describe `cost` need updating.
8. **New `stopReason` `"yielded"` (0.0.14).** It is sent only when the host gave the turn a deadline. agetor never sends one, so this value would reach the generic "unexpected stopReason" branch and settle the run as failed. That is harmless.

**Additive changes (opportunities)**

9. **Effort data is now published.** `fx models --json` lists, per model, `{id, name, efforts[], fast, ultrafast}` (0.0.14, spike S2). The ACP `effort` option for a model equals that model's `efforts` plus `auto` (S3). agetor's `parseFxModels` reads `ids` only (`src/bun/agent-discovery.ts:551-569`), so it still works, but it ignores the efforts, the labels and the fast flags.
10. **Fast and Ultrafast over ACP (0.0.13–0.0.14).** `configOptions` gains `{id:"fast", type:"select", currentValue:"true"|"false"}` on models that have a fast lane, and `{id:"ultrafast", …}` on Gateway models with that capability (`sessions.zig` diff 1957-2000). Both are set through `session/set_config_option`. `fx acp` gains `--ultrafast` and `--no-ultrafast` flags. Ultrafast is a higher-priced tier. agetor's `fast` field is cursor-only today (`src/shared/types.ts:371`).
11. **Steering (0.0.13).** `initialize` advertises `agentCapabilities._meta.fx.steering: true`. A `session/prompt` sent during a running turn becomes a steer. Its reply is `{stopReason, _meta:{fx:{steering:"absorbed"|"dropped"}}}`, and the delivered text is replayed as `user_message_chunk` with `_meta.fx.steering` (types.zig diff). agetor queues a follow-up sent during a turn as the next turn (`fxTurnQueue`, `src/bun/orchestrator.ts:4585`, `sendFxTurn` `:4700`, `drainFxQueue` `:4924`).
12. **Client system prompt (0.0.13).** `sessionCapabilities.systemPrompt` means `session/new` accepts a system prompt from the client in append mode (`client_instructions.zig`). Agent-profile instructions could travel this way instead of the `<agent_instructions_defined_by_the_user>` preamble.
13. **Structured notices (0.0.14).** A client that advertises `clientCapabilities.session.notices` receives `sessionUpdate:"notice"` (`server.zig:2486`). Without it, context warnings still arrive as agent text that starts with `[context] ` (`prompt.zig` `pushContextNotice`). That prefix is unchanged (`src/builtins/context.zig:221,878,975,1077`), so agetor's `isFxContextDiagnostic` (`src/bun/fx-acp.ts:1507`) keeps working.
14. **Tool-call identity metadata (0.0.14).** `tool_call` carries `_meta.fx.toolCall{internal, mcp?{server,tool}}`. `internal: true` marks fx's own discovery steps (`capability_search`, `mcp_select_tool`) that a host may hide (`tool_call_presentation.zig` diff).
15. **The auto-mode reviewer model can be chosen (0.0.11).** The `review_model` setting or the `FX_REVIEW_MODEL` env var picks the model for auto-mode safety reviews (`src/core/config/config_runtime.zig:666`, `src/builtins/gateway/permission_reviewer.zig:49`). The compiled default is still `openai/gpt-5.6-luna`, the reviewer that returns 403 on standard-plan accounts (memory: `project_fx_auto_mode_reviewer_403`). agetor already applies a harness's `env` map to the spawn (`src/bun/agents.ts:385`), so a user can set `FX_REVIEW_MODEL` today through Settings → Harnesses.
16. **Other changes:** fx's own default model is now `spacexai/grok-4.7` (0.0.11), while agetor pins `zai/glm-5.3-flash` (`src/shared/types.ts:2528`). Release binaries require macOS 15 or later (0.0.14). Commands fx launches receive `AI_AGENT=fx` (0.0.14). Since 0.0.13, terminals started by the shell tool stop when fx exits. agetor runs one `fx acp` child per turn, so a background process the agent starts in one turn (a dev server, say) dies when that turn ends. On 0.0.10 it survived until the next resume. Sessions v2 (`--sessions-v2`) is opt-in; ACP still saves v1 sessions with 12-character ids (S4).

**Unchanged (re-verified on 0.0.14)**

`--help` still contains "coding agent" ("Fast, native coding agent for the terminal."), so `FX_HELP_MARKER` matches. `fx acp --model/--log-file` (S1). The `initialize` shape. A dummy key still gives `session/new` OK and then `session/prompt` → `{stopReason:"refused", usage:{}}`, with "AI_GATEWAY_API_KEY authentication failed · HTTP 401" as assistant prose. The `status --json` auth fields (`auth`, `auth_help`, `auth_refreshable`) are unchanged; 0.0.14 adds `permission_mode`, `mode`, `modes`, `effort` and `ultrafast_requested`. `status --json` and `models --json` write nothing under an empty `HOME`. `FX_PERMISSION_MODE=yolo` still parses, and the session reports `full-access`. `session/resume` (agetor's follow-up path) works across processes (S4). `continueRecovery` still exists.

### 1b. fx: the effort table is stale, and the cause is the Gateway, not fx

Of the 36 curated fx ids in `AGENT_OPTIONS.fx.models` (`src/shared/types.ts:3731+`), the effort sets in `MODEL_EFFORT_SUPPORT.fx` (`:3290+`) differ from the live sets for **22**. Three curated ids are **gone from the catalog**: `alibaba/qwen3-coder-plus`, `mistral/devstral-2` and `anthropic/claude-3-haiku` (S2). Examples:

- `zai/glm-4.7`: agetor lists no efforts; the live set is `none/low/medium/high`. The same holds for `zai/glm-5v-turbo`, `grok-build-0.1`, `kimi-k2.7-code` and `gemini-2.5-flash`.
- `deepseek/deepseek-v4-flash`: agetor offers `xhigh/high`; the live set is `none/low/medium/high`. An agetor task set to `xhigh` gets the "isn't offered" breadcrumb and runs at fx's default.
- `spacexai/grok-4.7`: agetor lists none; the live set is `low/medium/high/xhigh`.
- `openai/gpt-5.2`, `gpt-5.4-mini`, `gpt-5.5` and `gpt-5.6-sol` now also offer `minimal`. agetor already has a `minimal` effort id (`src/shared/types.ts:3119`).

The installed **fx 0.0.10 reports the same new sets** over ACP (S5). The Gateway catalog moved; the fx release did not cause this.

### 1c. Cursor

1. **agetor does not use the Cursor SDK.** It drives the `cursor-agent` CLI in print mode inside tmux (`src/bun/cursor-tmux.ts`, argv at `src/bun/agents.ts:595-635`). The 2026-07-10 plan (`docs/plans/cursor-sdk-integration.md` §3 decision 1) chose the CLI over `@cursor/sdk` for three reasons: the SDK runs inside the Bun main process, so a restart mid-turn kills the run; the SDK needed Node ≥22.13 plus native platform packages, and Bun compatibility was unverified; and there is no tmux-survival story. **None of the SDK release notes from 1.0.20 to 1.0.35 apply to the current code.** The SDK has reached 1.0.40 on npm (published 2026-10-20), ahead of what the notes page lists.
   - What the notes do change: 1.0.20, 1.0.21, 1.0.23 and 1.0.28 fix SDK imports, `send()`, stream stalls and `bun build --compile` under Bun. That removes the Bun reason. The restart reason still holds: the SDK's "detached" runs are replays read back from its store (`toDetachedStoreRun`, usage snapshots "for detached/replayed runs" in `dist/esm/run-store-public-types.d.ts:89`), not live processes that survive the host. `engines` still says `node >=22.13`, and the package is 25 MB plus a per-platform native package.
2. **The cursor-agent CLI changelog (v2026.08.11 → v2026.10.08) has no breaking change for `-p --output-format stream-json`.** The documented envelope is unchanged (`cli/reference/output-format.md`). Relevant entries: headless runs now wait for their subagents before exiting, and headless keeps Max-mode variants (08.11); persistent sessions via `agent persist` (08.26); ACP subagent sessions (09.15); `--model` runs the exact id even when it is a prefix of another (09.28); ACP wakeups from watched shells, plus fixes to tools and summarization (10.08).
3. **The live stream on 2026.10.19 contains things the docs say it does not** (S7):
   - `type:"thinking"` events, `subtype:"delta"` with `text` and then `subtype:"completed"`. The docs say thinking is suppressed in print mode. `mapCursorEvent` drops them in its default case (`src/bun/cursor-tmux.ts:265-268`), so cursor runs show no thinking stream in agetor.
   - `result.usage = {inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens}`, the same shape as fx's prompt usage. agetor ignores it.
   - The inner `tool_call` object now carries `hookAdditionalContexts`, `toolCallId`, `startedAtMs` and `completedAtMs` **next to** the `*ToolCall` key. `bestEffortToolName` takes the *first key* when there is no `name`, `tool` or `tool_name` field (`src/bun/cursor-tmux.ts:141-153`). The `*ToolCall` key happens to come first today, so names still resolve. If that order ever changes, names break, and so does `detectCursorPlan`, which keys on the name `createPlanToolCall`.
   - Events gained `model_call_id` and `timestamp_ms`. `call_id` still contains an embedded `\n`.
4. **Workspace trust gates headless runs.** `cursor-agent -p` without `--trust`, `--yolo` or `-f`, in a directory with no trusted ancestor, exits 1 with no stdout and prints "⚠ Workspace Trust Required … Pass --trust, --yolo, or -f" (S6). agetor's cursor **Read-only (`ask`)** mode passes none of these flags (`src/bun/agents.ts:620-623`), so on any machine whose `$HOME`, or whatever folder contains `~/.agetor/worktrees`, is not trusted, every Read-only cursor run fails. **Trust is inherited from an ancestor** (S7). On the owner's machine `~/.cursor/projects/Users-alamosaravali/.workspace-trusted` exists, so the bug never shows there. The prod DB has 808 cursor runs, all in `auto` mode and none in `ask` (read-only query), so the failure has never been seen in practice. Auto mode passes `--force`, which skips the trust gate.
5. **The CLI has an explicit `--mode plan|ask` and `--plan` (cursor-agent `--help`).** agetor maps Plan to its own `ask` (`CODE_PLAN_MODE.cursor = {code:"auto", plan:"ask"}`, `src/shared/types.ts:3065`). Its modes are `auto` ("Auto (force)") and `ask` ("Read-only"), and Read-only emits no mode flag (`:3604-3607`). Other new flags: `--auto-review` (a server classifier), `--approve-mcps`, `--trust`, `--add-dir` and `--plugin-dir`. The CLI also has an ACP server (`agent acp`) with `session/request_permission` and the extensions `cursor/ask_question`, `cursor/create_plan`, `cursor/update_todos` and `cursor/task`.
6. **The model catalog is fine.** Every key in `CURSOR_MODEL_SPECS` (`src/shared/types.ts:2608`, 40 keys) still exists in `--list-models` (265 rows). Two new families are uncurated: `muse-wonder-1.0-*` and `muse-spark-1.3-*`. Discovery already surfaces them.

## 3. What we're assuming

1. **A real 429 storm on 0.0.14 keeps retrying and does not pause.** This is source-derived (`decide()`, plus "never pauses transient failure" in its tests) and was not run live, because the owner's fx login is `missing`. *If wrong:* the auto-resume engine still matters as it does today, and only the `failed`-state fix is needed.
2. **A `paused` update with `requiredAction: continue_later` on 0.0.14 can still be resumed with `continueRecovery`.** The method exists, but the trigger paths have changed. S4 shows that even an auth-refused turn leaves a `paused`/`continue_later` checkpoint that replays on resume. *If wrong:* Resume would answer "No paused model response to continue". agetor already surfaces that message verbatim (`src/bun/fx-acp.ts` continueRecovery `-32602` branch).
3. **Steering via a second `session/prompt` works for agetor's one-child-per-turn model.** This is source-derived from the capability flag and the reply shape; it was not exercised. *If wrong:* follow-ups keep queueing, which is today's behaviour.
4. **`_meta.fx.profileMcpServers: true` is ignored harmlessly by 0.0.10–0.0.12**, because `_meta` is extension space. Not exercised on old binaries. *If wrong:* the opt-in would need a version gate.
5. **The 3 catalog-missing curated fx ids are really retired**, not just hidden from unauthenticated callers. This could only be measured unauthenticated (264 ids, `private_models_hidden: true`). *If wrong:* retiring them would remove models a signed-in account can still run.
6. **cursor-agent's `thinking` events are a stable feature**, not a leak: they contradict the docs. *If wrong:* mapping them is harmless; they would just stop appearing.
7. **The Cursor SDK's local runs cannot outlive the host process.** This is inferred from the type declarations (store replay, not reattach); it was not exercised. *If wrong:* an SDK driver could meet agetor's restart-survival rule, and the CLI-vs-SDK decision would be worth reopening.

## 4. What we must ask the owner

Numbered by impact. "Rec." is the recommendation the evidence supports.

1. **Target version.** Should we verify against fx 0.0.14 and stay graceful on 0.0.10–0.0.13, upgrade this machine to 0.0.14, and run a paced live smoke? The smoke needs `fx login`, because the owner's fx is signed out right now. *Rec.:* yes to all three. Never touch `~/.fx` from a spike: always use an isolated HOME, as here.
2. **The fx mode nudge (a real bug on 0.0.14).** On 0.0.14 the best-effort `session/set_mode` (`src/bun/fx-acp.ts:2192`, `:2608-2613`) never sends `code`, because `code` is no longer listed. For `ask` it **writes `permission_mode: ask` into the user's own `~/.fx/settings.json`**, and their interactive fx then starts in Ask. `FX_PERMISSION_MODE` already sets the mode on every supported version (S3; documented since 0.0.8). *Rec.:* remove the nudge entirely, and add a release note for users whose profile was already flipped. agetor should not repair `~/.fx/settings.json` itself. The owner's `lastMode:fx` is `ask`, so this would hit them on the first upgrade.
3. **Profile MCP servers.** On 0.0.13 and later, should agetor send `_meta.fx.profileMcpServers: true` on new, resume and load, so fx tasks keep the user's profile MCP servers as they had through 0.0.12 and as every other harness does? Or should it accept fx's safer new default and offer project and client servers only? *Rec.:* opt in, because it matches running fx in a terminal. This is a security-posture call, so it belongs to the owner.
4. **fx efforts.** Should `discoverFx` read `models[].efforts` (plus `auto`) so that discovered efforts win over the curated table, the same rule codex follows (decision `785c5209`)? Should the curated `MODEL_EFFORT_SUPPORT.fx` also be refreshed to the 2026-10-22 sets (22 changes)? *Rec.:* both. With discovery alone, a fresh install or a probe failure would fall back to wrong data. Existing task efforts stay valid under the union retention rule, and the prod DB holds only 2 fx tasks, both with no effort set.
5. **fx Fast and Ultrafast.** Should agetor's `fast` task field (cursor-only today) also cover fx, through the ACP `fast` option on models whose catalog says `fast: true`? And Ultrafast, a higher-priced Gateway tier? *Rec.:* Fast yes, reusing the existing field and picker. Ultrafast no, or a later follow-up, because of cost.
6. **Retire 3 curated fx rows** that the catalog no longer lists (`alibaba/qwen3-coder-plus`, `mistral/devstral-2`, `anthropic/claude-3-haiku`)? Retiring touches `tasks.model`, the `lastModel:fx` pref and agent profiles (knowledge `c1efe6a2`). *Rec.:* retire them, with a kind-joined migration, after re-checking with a signed-in catalog if one is available (assumption 5).
7. **fx recovery UX now that transient failures never pause.** (a) Keep the auto-resume engine as is, add the `failed` state (terminal, not resumable, with a summary line), add labels for the new `connectivity_lost`/`compaction_prepared` causes and the `checking_liveness` action, and reword the copy. (b) Also add an agetor-side cap that stops a turn stuck in recovery after N minutes. (c) Remove the engine. *Rec.:* (a). fx's throttle bounds the cost, and older binaries and genuine pauses still use the engine.
8. **fx steering.** Should a follow-up sent during an fx turn be delivered into the live turn (`session/prompt` as a steer), the way claude-code folds follow-ups, instead of being queued? Turns can now retry for a long time, so a queued follow-up may wait a while. *Rec.:* in scope only if the owner wants parity now; otherwise record it as a decided follow-up. It changes `sendFxTurn` and `drainFxQueue` semantics.

## 7. Risks & blast radius

- **Mixed fx versions in the field.** Users can sit anywhere from 0.0.4 to 0.0.14. Each change must degrade cleanly: no nudge is fine everywhere, since the env var is honoured from 0.0.8; the `_meta` opt-in is assumed harmless before 0.0.13 (assumption 4); discovered efforts fall back to the curated table when `models[].efforts` is absent (0.0.13 and earlier); and a `fast` option is used only when the session advertises it.
- **User-profile side effects.** The nudge bug writes outside agetor's data dir. Removing it is the fix; the damage already done can only get a release note.
- **Security posture.** Opting into profile MCP (Q3) and passing `--trust` (Q13) both widen what an agent session loads. Both match what the user gets running the CLI themselves, but both are the owner's call.
- **Recovery semantics.** Turns that never pause can sit in `running` for hours. RunPanel's amber notice, the board card and the pipeline runner all treat that as a live step. A pipeline step waiting on fx recovery blocks its pipeline indefinitely. Note this when deciding Q7.
- **Effort and model catalog churn.** The Gateway changes efforts and ids without an fx release (S5), so a curated-only table goes stale again. Discovery-first (Q4) reduces how often a manual refresh is needed.
- **Cursor mapper changes.** A `thinking` stream adds rows to `run_events` (deltas must be coalesced, or RunPanel shows one bubble per token, as fx did on 0.0.7). `line_uuid` must stay stable across a reattach replay, so it should be keyed on the line index of the block's first delta, as the existing scheme does. A tool-name extraction change touches `detectCursorPlan`.
- **Tests do not pin any of this today** (§2, last row). The plan must add unit tests for: no `set_mode` sent; the `profileMcpServers` meta on all three handshakes; `failed` recovery state parsing and rendering; fx efforts from discovery; cursor thinking coalescing; and tool-name extraction with the new inner keys. It must also update the fake ACP server to the 0.0.14 modes.
