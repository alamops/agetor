## 1. Objective & success criteria

Opening a terminal on a task whose worktree checkout drifted off the recorded `task.branch` must open a shell at the worktree as it is, never run `git checkout`, and never show the red toast `worktree is on "<live>" not "<task.branch>" and could not be switched`. Drift is tolerated everywhere, never adopted: `task.branch` keeps meaning "the branch agetor created", and every surface that needs the real branch reads it live from git or from a new server-managed last-seen-checkout column.

Done means:

1. `prepareWorkdir`'s reuse path performs no `git checkout` for any caller (terminal open, Run/re-run, pipeline Retry/Advance/Restart, step reuse). A drifted, dirty, untracked-only, or detached-HEAD worktree all reuse in place.
2. A new `tasks.checkout_branch` column (migration `063`) records the branch agetor last observed checked out, refreshed at run start, run settle (every harness kind), terminal open and archive — never from the git-status GET poll. Server-managed: targeted UPDATE, no `updated_at` bump, excluded from the generic `tasks.update` SET clause and from `ALLOWED_PATCH_FIELDS`.
3. Archive records the live branch before detaching; unarchive and the `sendInput` restore re-materialize onto the recorded branch, falling back to `task.branch` (with a status line) when that branch no longer exists.
4. Delete removes `task.branch` and, when the live (or last-seen) checkout is a different named branch, that one too — never the repo default branch, never a PR-head task's recorded branch, never a branch another task holds. Both names are shown in the webview confirm dialog and in `agetor rm` output through a new read-only preview route; `DELETE /tasks/:id` still answers 204 with no body.
5. "Create PR" uses the live branch when it differs from `task.branch` and isn't the default branch; PR-head tasks (`branchSource: "existing"`) keep `task.branch`.
6. Drift is visible on the RunPanel header chip and Task-details rows (live, from the 5 s git-status poll), the Worktrees page (live, per row), the board card, `agetor show` and `agetor ls` (display-only last-seen value, falling back to `task.branch` while null). PR-head tasks get a warning-toned badge and a stronger run-log warning.
7. Every run start on a drifted worktree writes the status line `worktree is on <live> (task branch <task.branch>) — running there`.
8. The pipeline parent carries the last-seen checkout; step rows mirror it; the M-R6 guard stays for the materialize path.
9. The owner's `~/.agents/skills/implement/SKILL.md` and `~/.agents/skills/execute-plan/SKILL.md` only cut `implement/<slug>` when on `main`/`master` (outside this repo, not committed).
10. Unit coverage for every rule above plus a new Playwright spec that drifts a fake-driver task's worktree, opens a terminal (new xterm readiness harness), and asserts the drift chip and the Create PR head. `bun run typecheck`, `bun test`, and the new e2e spec are green at every wave barrier.

## 3. Approach & key decisions

- **No checkout, ever, on reuse (D2/D11).** The reuse branch keeps its `symbolic-ref` read purely to *report* the live branch (`checkoutBranch` on `PreparedWorkdir`, additive) and returns `cwd`/`branch: task.branch` unchanged. Rejected: a terminal-only exception (every other caller has the same hazard — evidence: the pipeline runner already routes around it with M-R6) and adopting the live branch into `task.branch` (owner rejected, D2).
- **One column, one writer, four refresh points (D6/D8/D15).** `tasks.checkout_branch` + `tasks.setCheckoutBranch(taskId, value)`; written at run start (`startTaskInner`, from `prepared.checkoutBranch`), run settle (both branches of `attachDoneHandler`, via a new `readCheckoutBranch(dir)` helper), terminal open (`createTerminal`), archive (inside the teardown job, right before `detachWorktree`), and the pipeline parent's `refreshParentWorktree`. Never from a GET. Writes compare-then-write so an unchanged value is a no-op. **Column name `checkout_branch` / `Task.checkoutBranch`** — "the branch name agetor last observed checked out in the worktree; `null` = never observed, or detached HEAD at the last observation". Always stored, even when equal to `task.branch` (simpler invariant; drift is derived as `checkoutBranch != null && checkoutBranch !== branch`). Reasoning, not evidence: storing "same" explicitly lets `agetor show` print one honest line and lets unarchive restore without a second lookup.
- **Step rows mirror through the db layer (D14).** `setCheckoutBranch` on a row with `pipeline_parent_id` also writes the parent in the same call, so a step's start/settle (which run through the ordinary orchestrator paths) keeps the parent current with no runner change; `propagateWorktreeToActiveSteps` and `launchStep`'s insert copy it down. The M-R6 verify-only guard is untouched.
- **Unarchive/restore honour the recorded branch inside `prepareWorkdir` (D6).** The re-attach path prefers `task.checkoutBranch` when it is set, differs from `task.branch`, and `refs/heads/<it>` exists; otherwise it re-attaches `task.branch` and returns an additive `warning` string the caller logs. Doing it inside `prepareWorkdir` covers unarchive, the `sendInput` restore, and the pipeline refresh with no per-caller logic (§8 assumption 4 and 5 settled: yes to both).
- **Delete preview is a read route, not a response-body change (D3/D5, §8 assumption 1).** `GET /tasks/:id/teardown-preview` → `TaskTeardownPreview` returns the branches delete would remove, which it read from (`live` | `last-seen` | `task-branch`), and the excluded candidates with reasons. `deleteTask` recomputes the same plan at teardown time (the live read happens before `git worktree remove` destroys the directory) and passes it to `removeWorktree(task, { branches })`; the option defaults to today's rule so every other caller and test is byte-identical. A pure `planTeardownBranches(input)` in `worktree.ts` takes the other rows' names as an input set (the cycle constraint above); the orchestrator gathers them. `DELETE /tasks/:id` stays 204 — older webview/CLI builds keep working; a CLI talking to an older core treats a 404 from the preview as "no preview".
- **PR head rule (D7).** `prHeadBranch(taskBranch, status, branchSource?)`: PR-head task → `taskBranch`; otherwise the live `status.branch` when it is set, not ignored, not the default branch, and differs from `taskBranch`; else today's behaviour. Existing tests stay green (the "worktree branch wins" case uses a default-branch status).
- **Drift UI reads two different sources on purpose (D8).** Panel + Worktrees page read live git (already polled / per-row fetched); card + CLI read the stored last-seen value (no git spawn on the 2 s poll). A tiny pure helper `src/mainview/lib/branch-drift.ts` (`driftOf(taskBranch, observed)`) keeps the "is drifted" rule in one place for the webview.
- **Skill edit is a task in this run (D9)** executed against the owner's home directory; it is recorded in §9 and in the final report but never committed here.
- **Detached HEAD records `null` (D12).** A refresh on a detached checkout writes `null` (nothing is recorded "since there is no branch name"); unarchive then falls back to `task.branch`. Reasoning, not evidence — see §8.
- **Terminal readiness harness for e2e.** `TerminalView` gains `data-testid="terminal-open"` (both open buttons), `terminal-tab`, and `terminal-pane` with `data-ready="true"` flipped on the first binary frame from the PTY; `e2e/helpers.ts` gains `waitForTerminalReady`. The spec pins `SHELL=/bin/sh` through `backendEnv` for the same reason `terminals.test.ts` does.

## 7. Blast radius & risks

- **`removeWorktree` signature** is additive (`opts?`); `deleteTask` is its only production caller. The branch list is computed *before* the teardown job runs, from a directory that still exists; inside the job the directory is removed first, then each listed branch is `git branch -D`'d. A branch still checked out in the user's main checkout makes git refuse the delete (`Cannot delete branch … checked out at …`) — best-effort, matching today's behaviour, and the natural guard for a user who switched the worktree onto one of their own branches.
