Evidence gathered during this grill:

- **G1 — `FX_PERMISSION_MODE` exists in every supported fx.** Running `git grep -c FX_PERMISSION_MODE <tag> -- src` on the fx source checkout finds 4 references at each of `v0.0.4`, `v0.0.5`, `v0.0.6`, `v0.0.7` and `v0.0.8`. The env var therefore sets the mode on every version agetor supports, and removing the `session/set_mode` nudge needs no version gate. (The checkout is the investigation's `scratchpad/fx-src/repo`.)
- **G2 — the owner's signed-in Gateway catalog on 2026-10-22.** The owner ran `fx login` during the grill. On installed fx 0.0.10, `fx status --json` then reads `auth: "fx login"` with `auth_refreshable: true`. `fx models --json` returns **145 ids** (`private_models_hidden: false`, `shown_count: 145`, `more_count: 0`). The catalog does **not** contain `spacexai/grok-4.7`, `zai/glm-5.3-flash`, `alibaba/qwen3-coder-plus`, `mistral/devstral-2`, `anthropic/claude-3-haiku` or `moonshotai/kimi-k3`. It **does** contain `deepseek/deepseek-v4-flash` and `openai/gpt-5.2`, plus uncurated newcomers such as `deepseek/deepseek-v4.1-flash-1017` and its `-fast` twin. The raw output is in `/private/tmp/claude-501/-Users-alamosaravali--agetor-worktrees-bffb84f6-da1a-4f0b-a8e1-617789e7ce67/cede9184-29a1-46cc-9e9c-e70f449b63c6/scratchpad/signed-in/` (`status.json` and `models.json`). The catalog lives on the server and is scoped to the account, so measuring it on 0.0.10 gives the same ids that 0.0.14 would see.
- **G3 — cost of replacing `fast`.** `grep -rlw fast src e2e` finds about 64 non-test files (about 370 lines) and 106 test or spec files. No migration in `src/bun/migrations/` has ever used `DROP COLUMN`. The owner saw these numbers before confirming the enum (D12).

## One-way doors (all decided by the owner, listed so the plan treats them deliberately)

1. **Drop `tasks.fast` and `agent_profiles.fast`** after backfilling `speed` (D14). This is the repo's first `DROP COLUMN`. After it, an older agetor build reads every task as not fast.
2. **Retirement migration**: retired fx model ids in `tasks.model`, `agent_profiles.model` and the `lastModel:fx` pref are rewritten to the new `DEFAULT_MODEL.fx` (D10, D21).
3. **Installing fx 0.0.14 over `~/.local/bin/fx`**, after backing up the 0.0.10 binary (D8).
4. **`--trust` on cursor runs without `--force`** records workspace trust under `~/.cursor/projects/…` for each worktree path (D22).

## Assumptions still open

1. **A real 429 storm on 0.0.14 keeps retrying and does not pause.** This is derived from the source and was not run live. The paced smoke may confirm it opportunistically. *If wrong:* the engine (D5) still covers it, so the plan is unchanged.
2. **`continueRecovery` still resumes a `paused` / `continue_later` checkpoint on 0.0.14.** *If wrong:* Resume shows fx's "No paused model response to continue", which agetor already surfaces verbatim.
3. **Steering through a second `session/prompt` during a turn works with agetor's one-child-per-turn model.** This is derived from the source; the fake server and the live smoke must exercise it. *If wrong:* the queue fallback (D17) is today's behaviour.
4. **fx 0.0.10–0.0.12 ignore `_meta.fx.profileMcpServers: true` harmlessly.** *Check cheaply before replacing the installed binary*: one `session/new` with the meta on the installed 0.0.10, in an isolated HOME. *If wrong:* add a version gate on the meta.
5. **Cursor's `thinking` events are stable**, even though they contradict the docs. *If wrong:* the mapping is harmless and the events simply stop appearing.
6. **`--mode plan` and `--mode ask` behave headlessly with `--trust` as documented**, and may need `--approve-mcps` (D34). *If wrong:* the plan adds the flag or adjusts the labels after the smoke.
7. **SQLite `DROP COLUMN` works on the bundled bun:sqlite (3.35 or later)**, and no index, trigger, view or constraint references `tasks.fast` or `agent_profiles.fast`. The plan must verify this before writing the migration.
8. **`deepseek/deepseek-v4-flash` still runs on the owner's account on fx 0.0.14.** It is in the catalog (G2) and ran on 2026-09-14; the D8 smoke confirms it. *If wrong:* re-pick the default with the owner. This is not decided here.
9. **Accepted risk (owner, D5):** a turn that never pauses can keep a pipeline step `running` indefinitely; the user stops it manually. This is recorded so the plan doesn't treat it as an oversight.
