## 0. One-paragraph summary

Two defects compound. **(A) Trigger:** Claude Code ≥ 2.1.286 compacts an idle session ~54 min after the last turn ("Compacted while idle, before the prompt cache expired"). That writes a `user` JSONL line carrying the compaction summary (`isCompactSummary: true`, `isMeta` unset), which `isContinuationContentEvent` (`src/bun/claude-tmux.ts:994`) treats as fresh conversational content, so `maybeAdoptContinuation` (`:4157`) opens a phantom `origin: "continuation"` run (status line "auto-continued after background task", the summary rendered as a YOU bubble) with a turn slot nothing will ever settle — claude is idle. **(B) The owner's complaint:** the version-proof net that is supposed to close such a turn, `signalIdleSettle` (`:7093`), is gated on `paneShowsIdleInputBox` (`:6367`), which requires the live composer row to be a **bare** `❯`. Claude Code's prompt-suggestion feature (since 2.0.70; back-off tuning 2.1.283) renders a suggested next prompt as dim placeholder text *in that row* (`❯ Open the PR and merge it`), so the predicate reads "text in the composer", `stuckTurnFallbackArmed` (`:5223`) stays true, and `matchUnparsableModal`'s watchdog arm (`:5288`) registers the fallback card after 3 stable ticks. Result in prod (DB evidence below): a task sat `running` from 03:46:37Z to 05:36:54Z (1h50m) with an "unknown prompt" card, until the owner typed a real turn in the attached terminal. Both spikes prove the fix signal: placeholder/suggestion text is always rendered inside SGR-dim spans (`ESC[2m … ESC[0m`) with the cursor at column 2, while typed text is never dim; tmux `capture-pane -e` exposes that, plain `capture-pane -p` (what every scraper site uses today) cannot.

### 1.2 The trigger (agetor side)

- `isContinuationContentEvent` `src/bun/claude-tmux.ts:994-1008` returns `true` for **any** `user` line that is not a task-notification, not `isMeta`, and not one of the two local-command twins. It never looks at `isCompactSummary` (grep over `src/` for `isCompactSummary|compactSummary|compact_boundary`: zero hits). The `summary`-type line (`:1412`) and the `system`/`compact_boundary`/`informational` lines (`:1370-1409`) are handled as breadcrumbs or dropped — only the summary `user` line is live content to this filter.
- `maybeAdoptContinuation` `:4157-4213` (called from `dispatchLine` at `:4324`, before the dedup return) adopts when a factory is installed, no turn is in flight, the queue is empty and the line is content or a notification; it arms `continuationWatchdog` **only** for notification-triggered adoption — a content-triggered phantom has no watchdog at all (`:4206-4212`). `startContinuationRun` (`src/bun/orchestrator.ts:5587`) inserts a `running` run with `origin: "continuation"`, flips the card to `running`, and emits the status line `auto-continued after background task` (`:5587+40`) regardless of what actually triggered the adoption.
- Precedent: the identical class of bug — a non-human `user` line adopted as a continuation that nothing can settle — was fixed for the `/model`/`/effort` local-command twins in #194 (`373a685`), documented inline at `:975-993` ("The observed run sat `running` for 6 minutes with claude parked at a bare `❯`"). The compaction summary is the third member of that family (task-notification → #97, local-command twins → #194, compaction summary → this).
- History of the adoption filter: `1e28eb6` (#95, introduced), `55ef208` (#97, notification adoption + watchdog), `373a685` (#194, local-command exclusion). Tests: `src/bun/claude-continuation.test.ts` (23 tests; the local-command exclusion is pinned at `:250`, so the convention for pinning a new exclusion exists).

### 1.4 Claude Code 2.1.296 facts (binary at `~/.local/share/claude/versions/2.1.296`, changelog, docs, live pane)

## 3. What we're assuming

- **The suggestion always renders through the placeholder path** (dim, `value.length === 0`). Proven for the one live suggestion captured and for the startup sample; the binary's renderer has a single placeholder branch. If a future CLI drew suggestions as normal-colour text, an SGR detector would regress to today's behaviour (card), never to a worse one.
- **`tmux capture-pane -e` is cheap enough to replace `-p` on the scrape tick** (one call per second while a turn is in flight). `-e` only adds escape bytes on styled rows; the matchers would need a one-line SGR strip before fingerprinting, or a second capture only when the live row is non-bare. If `-e` turns out to perturb fingerprints (the `__external__` sweep and the 3-tick stability gate hash the pane text), strip before hashing.
- **Enter on an empty composer with a suggestion is a no-op on 2.1.296** (changelog 2.1.136 + docs say Tab/→ are required). Not live-verified here; a bare `Enter` goes out from agetor only on parsed modals and after a paste lands text (`:2498`, `:2518`, `:5697`, `:7697`, `:8487`, `:9869`, `:10513`), so even if wrong the exposure is an empty-composer Enter during the boot paste-verify loop — worth one keystroke in a follow-up spike if the owner wants certainty.
- **The compaction summary is the only remaining synthetic `user` shape** that reaches `isContinuationContentEvent`. Claude also stamps `isVisibleInTranscriptOnly` / `toolUseResult` shapes on some lines; none appeared in this session's JSONL after settle. If another appears, the same allow-list style fix applies.
- **Idle compaction will keep firing on agetor sessions** (≥ 200k-token contexts are routine on long tasks; agetor must not edit the user's settings to turn it off). Settle-on-idle must therefore work without a real end_turn.

## 4. What we must ask the owner

1. **Placeholder detection vs. switching suggestions off for agetor-spawned sessions.** Agetor can (a) read the live composer row with `capture-pane -e` and treat an all-dim row as bare (fixes suggestions *and* the startup `Try "…"` / `Message @…` placeholders, keeps the attached-terminal UX intact), and/or (b) export `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false` in the claude spawn env (one line in `buildCommand`; also saves one background model request per turn on the owner's plan, but removes a feature the owner may use when attached, and does nothing for the other two placeholder families). (a) is required regardless for the startup placeholder (the composer-clear verification can never pass on a fresh session today); (b) is a product/cost call. Recommend (a), offer (b) as a Settings → General toggle if wanted.
2. **Should a placeholder row count as "idle" for the idle-settle net immediately, or only for the watchdog veto?** Treating it as idle lets `signalIdleSettle` close the phantom turn (the right outcome once A is also fixed — e.g. a terminal-typed turn whose end_turn is somehow missed) and makes the composer-clear verification pass; the downside is nil because the composer genuinely holds no text. Confirm there is no case where the owner wants a suggestion-bearing idle pane to stay `running`.
3. **Rendering of the idle-compaction summary.** Today it is a YOU bubble ("This session is being continued from a previous conversation…"), misattributed to the user, inside a run row that says "auto-continued after background task". Options: a status breadcrumb (`context compacted while idle · 450k → 8.6k tokens`), a collapsible "Compaction summary" block (like the agent-instructions block in `MessageSegments`), or suppress the body entirely. Also whether the `system/informational` notice should surface as a status line.
4. **Adoption wording.** `auto-continued after background task` is emitted for every content-triggered adoption, including the owner typing in the attached terminal. Should it say what actually happened (`continued from the terminal` / `auto-continued after background task` / never for compaction)? Cheap to do while in `startContinuationRun`, out of scope if the owner prefers a minimal fix.
5. **Surface the suggestion in Agetor?** Once agetor can read it (plain text on the row), it could show "Claude suggests: …" with a one-click send in RunPanel. Pure scope question — not needed for the fix; default no.
6. **Should the 10-minute `turn stalled … an interactive dialog may be open` breadcrumb also be suppressed when the composer is idle (bare or placeholder)?** It fired on this phantom run and pointed the owner at a non-existent dialog. Small, but it is the same predicate family.

## 6. Runnability

- Start locally: `export PATH="$HOME/.bun/bin:$HOME/.local/bin:/opt/homebrew/bin:$PATH"`; `bun install` in a fresh worktree; `bun run dev` (Electrobun against `~/.agetor-dev`, never prod `~/.agetor`), `bun run dev:hmr` for webview work; headless smoke: `AGETOR_DATA_DIR=<tmp> AGETOR_API_PORT=<port> AGETOR_API_TOKEN=<t> AGETOR_DAEMON_IDLE_MS=0 AGETOR_DEBUG=1 bun src/bun/headless.ts`.
- Tests: `bun run typecheck`; `bun test`; per file `bun test src/bun/claude-tmux-scraper.test.ts`, `bun test src/bun/claude-continuation.test.ts`. Known pre-existing failures on `main` (tmux-socket ×2, reconcile cancel) — report as pre-existing. Don't run `bun test src/cli` under heavy load.
- E2E: Playwright (47 specs in `e2e/`), run with `bun node_modules/@playwright/test/cli.js test <spec>` (not `bunx`), one run at a time. The fake claude driver (`AGETOR_CLAUDE_DRIVER=fake`) bypasses tmux, so **the pane predicates are unit-test-only**; a live check is a manual smoke against a dev data dir (recipe in the spike row above — a suggestion appears only after a real turn, non-deterministically; the startup `Try "…"` placeholder is deterministic and exercises the same renderer).

## 7. Risks & blast radius

- `scrapeOnce` runs ~1 Hz on every live claude task; switching its capture to `-e` touches the fingerprinting of all four matchers and the `__external__` sweep — strip SGR before hashing or the fallback card re-registers every tick (the exact flicker #191 fixed).
- Treating a placeholder row as idle makes the idle-settle net close turns it previously carded. That is the intended fix, but it also means a genuinely wedged turn whose pane happens to show a suggestion will be *settled* (run `succeeded`, card → `review`) rather than carded — the same trade the net already makes for bare rows.
- Excluding `isCompactSummary` lines from adoption must not exclude terminal-typed human turns (`0cd3d955` above is the legitimate case) — key on the flag, not on "any non-agetor user line".
- The composer-clear path (`Escape Escape`) stays unchanged in keystrokes; only its predicates change. A double-Escape on an empty composer opens the rewind picker — the fix must make `paneShowsComposerText` false on a placeholder row so that path is never entered for one.
- The installed app is 1.0.0; the fix lands in the next release alongside #258/#266.
