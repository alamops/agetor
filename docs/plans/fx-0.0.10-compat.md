## 1. Objective & success criteria

Bring the fx harness's version-truth (driver header, probe/discovery comments, CLAUDE.md) from 0.0.8 to 0.0.10 — agetor never adopted 0.0.9, so this bump covers both releases — and pick up the two ACP-visible changes 0.0.9 introduced: (a) the **reasoning-effort config option** (`configOptions[{id:"effort"}]` on `session/new`/`resume`/`load` + `session/set_config_option {configId:"effort"}`), wired end-to-end so fx tasks get an effort picker like claude/codex, and (b) **structured replay of a paused checkpoint on `session/resume`** (real `tool_call`/`tool_call_update` frames where 0.0.8 sent one text blob), which the driver must stop re-emitting onto the resume run. Success: typecheck green, full `bun test` green, Playwright green (fx specs + full suite), every "verified against 0.0.x" claim cites 0.0.9/0.0.10 with today's evidence, an fx task can pick an effort that reaches fx over ACP (or explains why it didn't), and a post-green live smoke on the upgraded machine confirms the wire facts below.

**Changed in 0.0.9 (retained in 0.0.10):**
- **Reasoning effort over ACP.** `session/new`, `session/resume` and `session/load` results carry a fourth `configOptions` entry, after `provider`/`model`/`mode` — `{"id":"effort","name":"Reasoning Effort","description":"Controls how much the model thinks before responding","category":"thought_level","type":"select","currentValue":<label>,"options":[{"value":"auto","name":"default"},{"value":<v>,"name":<v>},…]}` — **only when the active model advertises efforts** (`sessions.zig effortConfigState`, sourced from the Gateway catalog's per-model `reasoning_options[{type:"effort", values}]`). `session/set_config_option {sessionId, configId:"effort", value}` sets it (`server.zig:2222-2247`): `auto`/`adaptive`/`default` parse to fx's default; a value the model doesn't list — including any unrecognized but well-formed id (`ReasoningEffort.parse` accepts any short alphanumeric name; probe: `bogus-value` → this error) → `-32602 "Reasoning effort is not available for the active model"`; a value fx can't parse at all (empty / over 64 bytes / bad chars) → `-32602 "Invalid reasoning effort"`; no option at all → `-32602 "Reasoning effort is unavailable for the active model"`. Live-verified on 0.0.10 that `set_config_option effort=high` echoes `currentValue:"high"` in its own response; persistence across `session/resume` is source-derived (`commitActiveSessionEffort` → `preferences_changed` → `session_log.zig` projection) AND live-verified in the §3.6 smoke (a fresh process's resume reported `currentValue:"high"`); on 0.0.8 the same call is a silent no-op. **Per-model advertised sets, live-probed for all 28 curated ids (spike `fx-0010-efforts`):** 16 models advertise efforts, 12 advertise none (`zai/glm-5v-turbo`, `zai/glm-4.7`, `spacexai/grok-4.6`, `spacexai/grok-build-0.1`, `moonshotai/kimi-k2.7-code`, `minimax/minimax-m3`, `alibaba/qwen3.8-flash`, `alibaba/qwen3-coder-plus`, `mistral/devstral-2`, `google/gemini-2.5-flash`, `anthropic/claude-3-haiku`, `anthropic/claude-haiku-4.5`). Distinct values seen: `auto, none, low, medium, high, xhigh, max` — every one already an agetor effort id except `auto`. The full table is in §3 (T1).
- **Structured replay of execution history.** `sendExecutionHistory` now emits real `tool_call` (status `pending`) + `tool_call_update` (`completed`/`failed`, with content) frames per historical call, interleaved with `agent_message_chunk` assistant text, instead of one text dump (`sessions.zig:1300-1450`). It runs on **`session/load`** (full history — agetor already discards that replay via `suppressUpdates`) **and on `session/resume`** via `sendPendingRecoveryUpdate` (`sessions.zig:803-830`): when a paused checkpoint exists, resume replays the paused turn's user text, its tool calls, its partial assistant text, then the `paused` recovery update — all BEFORE the resume response. Agetor's `session/resume` path only uses `state.replaying` to tag recovery sentinels, so on 0.0.10 those replayed tool frames would be re-emitted as `tool_use`/`tool_result` events onto the resume run (fresh `seenLineUuids` per turn; the `(run_id, line_uuid)` index is per run). On 0.0.8 the same window re-emitted a text blob as an assistant bubble — pre-existing, just less visible (a rate-limit pause at the first request has empty execution).
- Session titles are now LLM-generated in the background (`prompt.zig maybeStartAcpTitleTask`, gated by a `session_titles` setting) and still ride `session_info_update {title}` — no agetor change.
- `subagent` tool gained `model`/`effort` overrides and mid-task feedback; tool inventory names unchanged; renders generically.
- Cosmetic: `-c/--continue` help copy ("latest" → "remembered" workspace session).

## 3. Approach & key decisions

1. **Effort is wired end-to-end, curated + runtime-validated** (owner, §8 Q1). No discovery source exists for fx efforts (`models --json` carries none; the option only appears per session), so `MODEL_EFFORT_SUPPORT.fx` becomes the live-probed per-model table below and the driver validates against the `effort` option fx actually returns at `session/new`/`resume`, emitting a visible breadcrumb whenever the stored effort can't be applied. Unknown/discovered-only fx ids fall back to the default model's set (existing `supportedEfforts` rule) and rely on the same runtime validation.
2. **fx's own default is representable: a new global effort id `auto` ("Model default").** fx's default effort is `auto` (label "default"), and it is the value every effort-model reports at `session/new`. Rather than special-casing `null` through four pickers and `createTask`, `EFFORT_OPTIONS` gains one trailing row `{ id: "auto", label: "Model default", hint: "Let the model/gateway pick its own reasoning level — fx only today." }`, every effort-advertising fx model lists `auto`, and `DEFAULT_EFFORT.fx = "auto"`. So a new fx task keeps fx's default behavior exactly as today (no cost/latency change on the owner's free-tier account), and picking `high`/`max`/… is an explicit choice. The driver sends `set_config_option effort=auto` only when a resumed session's persisted `currentValue` differs (resets a mid-task change back to default); otherwise `auto` is silent. No other kind lists `auto`, so their pickers/tables are untouched. *Alternative considered:* `DEFAULT_EFFORT.fx = "high"` (house convention) — rejected because it silently changes every fx run's cost/speed on the owner's rate-limited account; flagged in §8 for the owner to flip.
3. **Driver effort application is best-effort and never fails the turn.** After `session/new` or a successful `session/resume`/`session/load`, read `configOptions` for `id:"effort"`. With a non-null `opts.effort`: option present ∧ value listed ∧ `currentValue !== value` → await `session/set_config_option {sessionId, configId:"effort", value}` (handshake timeout); success is silent. Option present ∧ value not listed → status `fx: effort <x> isn't offered for <model> (offers: <values>) — running at fx's default`. Option absent (0.0.8 binary or a no-effort model) ∧ effort ≠ `auto` → status `fx: <model> exposes no reasoning-effort setting — running at fx's default`. RPC error → status `fx: couldn't set effort <x> — <fx message> — running at fx's default`. Runs on every turn (fx re-validates per session; the persisted value makes repeats cheap).
4. **Replayed content is suppressed during `session/resume`** (owner, §8 Q2): while `state.replaying` is true, `handleServerNotification` forwards only `session_info_update` (recovery + title sentinels, exactly today's behavior) and drops `agent_message_chunk`/`agent_thought_chunk`/`tool_call`/`tool_call_update`/`usage_update`. Rationale: the run's persisted events already cover that history (same reasoning as the `session/load` `suppressUpdates` discard), and live turn output only starts after `session/prompt`. `session/load`'s "SCHEMA-DERIVED — unexercised" comment is corrected: 0.0.9+ replay is structured and still discarded wholesale.
5. **Version truth cites both releases**: "verified against fx v0.0.4, v0.0.6, v0.0.7, v0.0.8, v0.0.9 and v0.0.10" in the driver header; CLAUDE.md "verified through 0.0.10 (0.0.9 probed in the same pass — never adopted separately)". No `fx-0.0.9-compat.md`; this file is the record for both. `fx-0.0.8-compat.md` stays as history.
6. **Machine upgrade + live smoke after green** (owner, §8 Q3): `bash <(curl -fsSL https://fx.sh/setup.sh) v0.0.10` over `~/.local/bin/fx` (0.0.8 backed up in the scratchpad), verify `fx --version`, then paced live turns on `zai/glm-5.3-flash` with the real login: one Full-access turn with a shell call (records `session/new` configOptions incl. `effort`, the `set_config_option` echo for `high`, `usage_update`, `tool_call.name`), then a follow-up turn on the same session (resume: `effort.currentValue` persisted as `high`, no second set). Turns paced ≥ 20 s apart for the free-tier limit; stop and ask for `fx login` if credentials fail; never escalate to `auto` mode (reviewer 403 on this account).
7. **Fake driver parity** so effort is e2e-testable without fx: `spawnAgent` threads `opts.effort` + model into the fake; a new prompt marker `FAKE_FX_EFFORT_UNOFFERED_PROMPT_MARKER = "__agetor_fake_fx_effort_unoffered__"` (env twin `AGETOR_FAKE_FX_EFFORT_UNOFFERED=1`) makes the fake emit the "isn't offered" breadcrumb (with a fixed `offers: auto, low, high, max` list) for the task's effort; otherwise the fake is silent, mirroring the real driver's success path.

- `EFFORT_OPTIONS` gains `auto`: consumers iterate it generically (`supportedEfforts`, pickers, CLI `pickOption`, `effort-support.test.ts` "ultra first"). - `DEFAULT_EFFORT.fx` flips `high` → `auto`: previously unused (every fx set was empty). Existing fx tasks have `effort: null`; RunPanel's cascade and `effortFallbackForModelChange` will patch them to `auto` on next open/model change (both use `DEFAULT_EFFORT[kind]` when offered) — a no-op at runtime (auto is silent). No migration.
- Driver: one extra awaited RPC per turn on effort models (bounded by the handshake timeout); every failure degrades to a breadcrumb. Replay suppression only affects the `session/resume` window, which carries no live output.
- `modelDeclinesEffort` (curated-only) now returns false for effort-advertising fx models — it is only consulted on the claude-code path, so nothing changes.
- `PATCH /tasks/:id`'s null-clear guard now rejects `{effort: null}` for the 16 effort-advertising fx models (it always did for any model with a non-empty `supportedEfforts` set); the webview never sends a bare null (cascades patch to the fallback), `agetor edit --effort` only sends strings — API-surface only, behaving as designed.
- `EFFORT_OPTIONS` gaining `auto` also widens the DISCOVERED-effort path: `supportedEfforts` filters `EFFORT_OPTIONS` by a CLI's reported set, so a codex catalog that ever reported `auto` would have surfaced it; Phase 8 makes `auto` fx-only there (filtered out of the discovered branch for every other kind), keeping the codex/claude effort builders unreachable by construction.
- Rollback: revert the branch commits; no migrations, no data-shape changes. Machine: re-run the setup script pinned to `v0.0.8`.
