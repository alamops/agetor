## Assumptions still open

1. **A1: the 0.159.0 floor also applies to API-key codex accounts.** It was measured only on a ChatGPT plan, like every existing floor. *If wrong:* an API-key user is refused needlessly and can set `AGETOR_SKIP_CLI_VERSION_FLOOR=1`. The plan is unchanged.
2. **A2: Terra's `ultra` follows codex's catalog.** One live `ultra` turn succeeded. *If OpenAI drops it:* discovered efforts hide it automatically.
3. **A3: the investigation's measurements of the signed-in catalog (139 ids) and the unauthenticated catalog (262) still hold.** D9's 0.0.14 re-measure may move a model across the `catalogOnly` line. *If so:* D13's rule decides, and the counts follow D20's re-count rule.
4. **A4: the fx 0.0.14 upgrade is non-disruptive for the owner.** Agetor already targets 0.0.14 (#277). *If the setup script fails or the binary regresses:* the smoke falls back to 0.0.10, efforts come from the Gateway `reasoning_options` alone, and the plan records it.
5. **A5: codex may run Terra on its "priority" (Fast) tier by default** (investigation A4). This was not probed. *If true:* agetor's "Speed: Off" for Terra is inaccurate. The impact is cosmetic and is out of scope (D18).
6. **A6: Kimi K3.1 Pro has little web corroboration**, though it is a real Gateway id. The `catalogOnly` gate makes it fail-closed. *If it's withdrawn:* the row just never renders.
7. **A7: migration 075's volumes are unknown** (prod DB is out of bounds). The dev-DB-copy dry run (D8) measures the dev side. The migration's shape doesn't depend on volume.
