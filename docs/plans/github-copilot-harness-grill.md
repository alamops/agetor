**Shape of the work.** Copilot ships as a seventh `AgentKind` (`copilot`). It uses a **tmux one-shot driver**, `copilot --output-format json --session-id <uuid>` with the prompt on stdin, cloned from `antigravity-tmux.ts`/`gemini-tmux.ts`. It is **enabled by default** with the experimental badge and defaults to the model **`auto`**. It offers three modes (Auto / Plan / Read-only). v1 includes a **plan approval card** and six parity features (thinking, usage chip, skills/MCP discovery, CLI version floors, subagent tabs, multi-account template). The four silent kind fallthroughs become exhaustive throws. The bar is a real-binary BYOK test, Playwright e2e on the fake driver, **and a live smoke on the owner's real Copilot login**.

## Assumptions still open

- **The owner has a Copilot plan that includes the CLI and will install and log in** (`brew install --cask copilot-cli` then `copilot login`) before the live-smoke step. The device/browser login needs a human, so the implementing agent can't do it alone. *If wrong:* D15(4) can't run. The mapper ships verified against BYOK only, and that has to be stated in the final report, not silently skipped.
- **The real Copilot backend emits the same JSONL as BYOK runs** (investigation §3). *If wrong:* the live smoke catches it, and the mapper needs a capture-driven fix before merge.
- **`assistant.reasoning` appears on stdout for reasoning models.** *If wrong:* D11(a) degrades to the gemini parity gap (no thinking stream), and the plan must say so instead of shipping dead code. The fallback is `assistant.message.reasoningText`, if present.
- **`exit_plan_mode.requested` may not appear in `-p` mode.** D5 reads `plan.md` as the primary source for that reason. *If plan.md isn't written in `-p`:* the plan card has no source, and the live smoke decides.
- **`COPILOT_ALLOW_ALL=true` plus `--allow-all` together cover tools, paths and URLs** in Auto (spike: the env var trusts and works with `--session-id`). *If wrong:* Auto may still deny some writes. Verify in the BYOK test.
- **A separate `COPILOT_HOME` isolates a second account** (the keychain entry per login). *If wrong:* the multi-account template (D12) needs a `HOME` override or a per-harness `COPILOT_GITHUB_TOKEN`. Verify in the live smoke if a second account is available, else record it as unverified.
- **Copilot's per-model support for each effort level is unknown**, so D7's tables are borrowed from other kinds. *If wrong:* harmless, because Copilot reports and ignores an unsupported level. The plan should surface that report as a status line (fx's breadcrumb precedent).
- **Copilot-only model ids** (`mai-code-1.1-flash`, `claude-opus-4.8-fast`, …) have no borrowed effort table. The planner decides their list, defaulting to the full none…max set plus Model default.
- **Older CLIs refuse newer model ids** (the codex precedent). The changelog-derived floors (D11(d)) assume they do. *If wrong:* the floors are unnecessary but harmless (fail-open on an unparseable version).
- **Migration number** is unknown until merge order is known (D26). Three branches currently want slots after 074.
