## 1. Objective & success criteria

Replace how agetor drives **OpenCode 2.x** turns: instead of one `opencode run --format json` client per turn inside tmux, agetor talks to an **agetor-owned `opencode serve` per harness** (hosted in tmux) over its HTTP + SSE API. OpenCode 1.x keeps the existing tmux `opencode run` driver unchanged.

Success criteria (each: production path → test that drives it):

1. **Steering.** A message sent while a v2 turn runs is delivered into that turn (`session.prompt` with `delivery:"steer"`) and the model answers it in the same turn; no new run is minted. Path: `POST /runs/:id/input` → `sendInput` → `sendOpencodeTurn` → active handle `steer()` → `opencode-driver` → `opencode-http.prompt`. Test: orchestrator test + e2e against the fake server.
2. **Restart survival.** A v2 turn in flight when agetor restarts keeps running inside the tmux-hosted server; on boot agetor re-adopts the server, catches up from the message snapshot and streams the rest into the same run, which settles normally. Path: `reconcileOrphans` → `reattachOpencodeServerTurn`. Test: orchestrator test (driver torn down and rebuilt against a live fake server).
3. **Permission cards (Ask mode).** In the new Ask mode every tool call raises a card; Allow once / Always / Reject (optional user-typed reason) answers it over HTTP; a reject lets the model continue. Auto approves silently; Plan uses OpenCode's plan agent. Path: hub `permission.asked` → driver → `registerOpencodePermission` → card → `/fx-permissions/:id/answer` → `opencode-http.replyPermission`. Test: e2e + driver test.
4. **Question cards.** OpenCode's question tool shows on the shared ask card (every mode); answers (options or free text) and Skip (empty answer, or the user's typed reason) go back over HTTP; the model continues. Path: hub `form.created` → `registerOpencodeAskQuestions` → `/ask-questions/:id/answer` → `replyForm`. Test: e2e + route test.
5. **Live subagents.** A child session's events stream into its subagent tab live (no turn-end export on v2). Path: hub `session.created{parentID}` → `opencode-subagents.ingestOpencodeChildEvents`. Test: driver/subagent test.
6. **Server wake.** When OpenCode starts an execution on a task's session with no active agetor run (background subagent finished), agetor mints a run (`origin: "agent"`), moves the card to Running, streams, settles to Review/Ready. Path: hub → orchestrator `onOpencodeServerWake`. Test: orchestrator test with the fake server's wake scenario.
7. **Stop / delete / archive / agent switch** interrupt the v2 session over HTTP (`session.interrupt`), cancel open cards, and never hang. Test: orchestrator + e2e Stop.
8. **Server lifecycle.** One server per harness, started on demand (single-flight), random password generated by agetor, adopted on boot, stopped after 30 min with no running turn or open card, and on a real app quit when idle; never stopped while a turn runs. Test: `opencode-server.test.ts`.
9. **Shared/Standalone option retired** everywhere it is shown or set (UI, CLI, profile forms); stored columns kept and ignored. Test: webview/CLI unit tests updated.
10. The uncommitted Zen/Go label fix already on this branch ships as its own commit first.

## 2. Context & constraints

Grounded findings (Phase 1 briefs + spikes, 2026-11-03, OpenCode v2.1.3 Homebrew, model `opencode-go/deepseek-v4.1-flash`):

- **ACP rejected for steering** (live): `opencode acp` answers a second `session/prompt` on a busy session with `-32603 "Session already has an active ACP prompt"`. Source: `packages/cli/src/acp/turn.ts:377-389` at v2.1.3.
- **HTTP API** (live spikes `scratchpad/spikes/opencode-steer-http`, `opencode-http-client`; source brief):
  - Auth: HTTP Basic `opencode:<password>`; `opencode serve` takes its password from `OPENCODE_PASSWORD` (else prints a random one). `GET /api/info` is authenticated.
  - One serve runs sessions in many directories: `POST /api/session {title, agent, model:{providerID,id,variant}, location:{directory}, permissions:[{action,resource,effect}]}`; every `/api/session/{id}/…` call is scoped by the session.
  - Turn: `POST /api/session/{id}/prompt {id?:msg_…, text, delivery:"steer"|"queue"}` returns the inbox item at once; `session.inbox.delivered{inboxID}` marks promotion; terminal = `session.execution.succeeded|failed|interrupted`.
  - Events: one global SSE `GET /api/event` (`data:` frames, 15 s heartbeat, no replay, 4096-event subscriber queue). Shapes: `session.text.delta/ended`, `session.reasoning.*`, `session.tool.input.*`/`called`/`progress`/`success`/`failed`, `session.step.ended{cost,tokens}`, `session.usage.updated`, `session.created{parentID}`, `permission.asked/replied`, `form.created/replied/cancelled`, `session.retry.scheduled`.
  - Catch-up: `GET /api/session/active`, `GET /api/session/{id}/message?order&cursor&limit≤200` (includes running tool parts), `GET …/permission`, `GET …/form`. The experimental `…/log?after=` returned nothing live — not used.
  - Replies: `POST /api/session/{sid}/permission/{rid}/reply {decision:"once"|"always"|"reject", message?}` (reject with message → model continues; spike-verified); `POST /api/session/{sid}/form/{fid}/reply {answer:{q0:…}}`; `DELETE …/form/{fid}?message=` (no message → turn interrupted).
  - `POST /api/session/{id}/interrupt` (55 ms; session reusable). Turns outlive the client: `kill -9` of the client mid-turn, reconnect, turn finished in the server (spike Q8, Q10 with serve in tmux).
  - Default Build agent asks for almost nothing; Ask mode = session `permissions:[{action:"*",resource:"*",effect:"ask"}]` (per-session rule spike-verified with `shell`; the `*` form is to be verified in wave 1).
  - Todo: only with `experimental.todo` (owner decision G10 stands: no config injection); `todowrite` input/metadata mapped as today.
  - v1 (1.19.x) HTTP API differs (no `/api`, no inbox/delivery) — out of this driver.
- **Existing surface** (brief 1): the tmux driver `src/bun/opencode-tmux.ts` (1,096 lines), `buildCommand`/`spawnAgent` opencode branches (`src/bun/agents.ts:911-980`, `:4015-4050`), orchestrator queue + reattach (`sendOpencodeTurn` `orchestrator.ts:5646`, `spawnOpencodeTurnNow` `:5675`, `drainOpencodeQueue` `:5776`, `reattachOpencodeTurn` `:5811`, `reconcileOrphans` `:1086/:1101/:1151/:1287-1300`, `dropOpencodeTask` `:5797`), D-19 breadcrumb (`src/shared/opencode.ts:182-222`), subagents (`opencode-subagents.ts`), picker carriers (`OpencodeServerPicker.tsx`, `NewTaskForm`, `TaskLaunchPickers`, `AgentProfileFormDialog`, `AgentProfileDetailsDialog`, `CloneProjectDialog`, `CreateTaskFromIssueDialog`, `ResolveConflictsDialog`, `RunPanel`, `lib/agent-profile-form.ts`, CLI `add`/`manage`/`agent-profile`/`show`/`usage.ts`).
- **Card plumbing** to reuse: `registerFxPermission`/`answerFxPermission` (`src/bun/interactions.ts:828-880`) + `/fx-permissions/:id/answer` (`server.ts:7188`) + `FxPermissionCard` (`RunPanel.tsx` ~8845); ask card `registerCursorAskQuestions` (`interactions.ts:585`) + `/ask-questions/:id/answer` (`server.ts:6876`, branches on `source`); CLI `answer` (`src/cli/answer-logic.ts`).
- **ACP drivers** (brief 2): fx is the robust template for kill ladders and process reaping; cursor's orchestration shape matches OpenCode's.

Repo standards that apply:
- `CLAUDE.md` — every spawn via `coreSpawn` + `childEnv`; every route in `ROUTE_POLICY`; Bun main thread shared (cooperative work); agetor adds no text to what the model sees (`docs/architecture/pasted-content.md`); session ids harness-scoped (`findLastSessionIdForHarness`); persisted events stay raw; RunPanel per-task reset; a popover in a dialog follows the Escape contract; tests set `AGETOR_DATA_DIR` at top level and never run the real binary (`src/test-preload.ts`).

## 3. Approach & key decisions

**Chosen:** a native v2 client in four new modules plus wiring:

| Module | Role |
| --- | --- |
| `opencode-server.ts` | per-harness `opencode serve` manager in tmux: start (single-flight), adopt, health, idle sweep, stop |
| `opencode-http.ts` | typed HTTP client + resilient SSE reader |
| `opencode-hub.ts` | one SSE connection per server; dispatch by session id; child-session parentage; reconnect → catch-up callback; wake detection |
| `opencode-events.ts` | pure mapper: live events and message snapshots → agetor chunks with stable line uuids (so snapshot + live dedupe) |
| `opencode-driver.ts` | one turn = `SpawnedAgent` with `steer`, `kill`, `done`; permissions/forms/subagents/usage; reattach |

Decisions (E = spike/source evidence, R = reasoning, O = owner):
- D1 (O) Full HTTP client, not ACP (ACP rejects mid-turn prompts — E).
- D2 (O) One agetor-owned server per harness, tmux-hosted; never the user's OpenCode background service. Shared/Standalone picker retired; `tasks.opencode_server`/`agent_profiles.opencode_server` kept, ignored, still exported/imported in bundles for compatibility.
- D3 (O) v1 keeps the tmux `opencode run` driver.
- D4 (O) Modes Auto / Ask / Plan. Auto replies `once` to every `permission.asked` for the session and its children; Ask creates the session with an all-`ask` rule and shows a card per request; Plan = `agent:"plan"`. On v1, Ask runs without `--auto` (OpenCode rejects every ask) and posts a status line — deny over allow (R).
- D5 (O) Skip/Reject carry only a reason the user types. Empty Reject = plain `reject`; empty Skip = form reply with an empty answer object (if the server refuses it, the card says the turn will stop and Skip falls back to `DELETE` without a message — verified in wave 1). Agetor writes no words of its own.
- D6 (O) Server stop: 30 min with no running turn and no open card, and on a real quit when idle; never while a turn runs; a handoff between app and background core is not a quit.
- D7 (O) Server wake → new run `origin: "agent"`, card → Running.
- D8 (R) Password: 32 random bytes generated by agetor, passed as `OPENCODE_PASSWORD` in the server's env (so serve never prints it), stored in `dataDir/opencode-servers/<harnessId>.json` mode 0600 and read back with the no-follow helpers. Never logged, never in a URL. The URL is read from the server's log line (contains no secret).
- D9 (R) Breadcrumb: v2 server turns write `server=agetor`; `parseOpencodeTurnBreadcrumb` accepts it. Reattach routes by it: `agetor` → server reattach; `shared|standalone` → the existing tmux reattach (covers v2 tmux turns in flight at upgrade).
- D10 (R) Kill switch: `AGETOR_OPENCODE_TRANSPORT=run` forces the legacy tmux driver for v2 (rollback without a release).
- D11 (R) Steer while a card is open: still steer (OpenCode delivers it after the card is answered). Steer while the server is unreachable or on v1: queue as today, with a status line naming why.
- D12 (R) Old `ses_…` ids resume on the agetor-owned server when its data dir is the same one the shared service used (same HOME/XDG); a not-found session starts fresh with the existing `opencodeResumeFailedStatusLine`.
- D13 (R) Test seam: a fake OpenCode v2 server (`src/bun/fixtures/opencode/fake-serve.ts`, Bun) started by a stub `opencode` binary's `serve` subcommand; scenarios chosen by prompt markers. Unit tests may host it without tmux (`AGETOR_OPENCODE_SERVER_HOST=direct`, test-only, documented). The real driver, hub and manager run in unit and e2e tests; `AGETOR_OPENCODE_DRIVER=fake` stays for the v1/NDJSON paths.

Rejected: ACP (no steering on v2); steering the existing tmux driver through the shared service only (owner chose the full client); one server per task (memory scales with tasks — owner).

## 7. Invariants, runtime shape & risks

Invariants (and where each is enforced):
- I1 Agetor never adds words to anything the model reads: prompt text, steer text, permission reasons and skip reasons are the user's verbatim; Skip-empty sends an empty answer — `opencode-driver.ts` is the only writer of prompt/reply bodies.
- I2 One server per harness, one start at a time — `ensureOpencodeServer` single-flight map; no other code spawns `opencode serve`.
- I3 Never stop a server with a running turn or an open card — the `isBusy` predicate passed from the orchestrator is the only input to `opencodeIdleSweep`/quit stop.
- I4 The password never leaves the state file, the server env and the Authorization header — no log, argv, URL, event or error message carries it (`opencode-http` redacts errors).
- I5 One writer per run's events: the driver's mapper; snapshot and live share line uuids (`opencode-events`), so a resync never duplicates.
- I6 A card's answer is applied exactly once: `interactions.ts` registry + route in-flight guard; the server's `FormAlreadySettledError`/404 on a stale card closes the card without error.
- I7 Every spawn through `coreSpawn`/`childEnv` (tmux launch); HTTP via `fetch` to `127.0.0.1` only.
- I8 Resume uses `findLastSessionIdForHarness(taskId, "opencode_session_id", harnessId)` — no other session-id source.
- I9 Main thread: snapshot mapping and child ingestion run in ≤ 20 ms slices for large histories.

Runtime shape: one core process (app or background core — they hand off the port); servers live in tmux and outlive any core; a core crash mid-turn → the next core adopts the server and reattaches; a server crash mid-turn → hub reconnect fails → driver settles the run `failed` with a status line, next turn starts a new server and resumes the session from disk; provider down → OpenCode retries (`retry.scheduled` status lines) then `execution.failed`. Kill switch `AGETOR_OPENCODE_TRANSPORT=run` wins over everything.

Blast radius: every OpenCode v2 task; agent profiles/pipelines using OpenCode (field kept, picker gone); CLI scripts passing `--opencode-server` (warn, not fail); e2e opencode specs. In-flight at upgrade: v2 tmux runs reattach through the old path (breadcrumb `shared|standalone`). Rollback: kill switch, or revert; no migration to undo. Memory: ~120–200 MB per active harness server.
