## 1. Objective & success criteria

Add Google's `gemini-4-argon` (GA 2026-10-13, no `-preview`, no sibling ids) to every agetor harness that can run it, and — per the owner's grill decisions — sweep in three adjacent fixes:

1. **gemini** (Gemini CLI): a new top row `gemini-4-argon`, passed through verbatim with **no** `MODEL_MIN_CLI_VERSION` floor (D2); `DEFAULT_MODEL.gemini` stays `gemini-3.1-pro-preview` (D1); effort set `[]` like every gemini row.
2. **antigravity** (`agy`): three curated rows `gemini-4-argon-{high,medium,low}` on top (D3/D4, id unconfirmed); default stays `gemini-3.8-flash-high` (C2).
3. **cursor**: `CURSOR_MODEL_SPECS["gemini-4-argon"]` (high/medium/low, unsuffixed label → high, no minimal/fast/Max Mode) above 3.8 Flash + migration **064** normalizing stored variant ids (C3); cursor default stays `grok-4.7`.

5. **Antigravity effort fix** (D6/D7): every antigravity effort set becomes `[]`, migration **065** NULLs saved `effort` on antigravity-kind tasks and agent profiles, and the antigravity command builder never emits `--effort` again.
6. **Prune** (D8/D9): drop `gemini-3.7-flash` and `gemini-3.5-flash` from the gemini catalog and `gemini-3.7-flash-{high,medium,low}` from the antigravity catalog; migration **066** rewrites pinned tasks, agent profiles and `lastModel:*` prefs to 3.8 Flash (same effort suffix on antigravity). Cursor keeps its 3.7/3.6/3.5 Flash specs (live `cursor-agent models` still lists them).
7. **Docs** (D10/C9): a CLAUDE.md antigravity bullet under "Agent command shape", README "Six harnesses" + an Antigravity row, fx count pins nineteen→twenty.

## 3. Approach & key decisions

Owner decisions (D1–D10, C1–C9) are taken as given; see the grill record. The calls below are the planner's, each marked **evidence** (measured) or **reasoning** (convention/judgement).

1. **Three migrations, one purpose each** (A5): `064_normalize_cursor_gemini_4_argon` (fixed by precedent), `065_antigravity_effort_in_model_id` (NULL saved antigravity efforts + delete `lastEffort:antigravity`), `066_retire_gemini_3_7_and_3_5_flash` (the prune rewrite). *Reasoning:* the owner prefers one purpose per migration; each is independently testable and independently revertible-by-forward-migration; 065 and 066 commute. Rejected: folding 065+066 into one file (saves a file, loses the one-purpose property).
2. **Every rewrite is kind-joined** — `agent IN (SELECT id FROM harnesses WHERE kind = '<kind>')` / `harness_id IN (…)`; prefs are keyed by kind in the key itself (`lastModel:gemini`, `lastModel:antigravity`, `lastModel:cursor`). *Evidence:* §2.6 collisions. Cost: a task whose harness row was deleted (049's "orphan case") is not rewritten and renders as an unlisted row — accepted, since Cursor's live catalog makes an un-joined rewrite actively wrong.
3. **Prefs are UPDATEd to the successor, not DELETEd** (`lastModel:gemini` 3.7/3.5 → `gemini-3.8-flash`; `lastModel:antigravity` 3.7-x → 3.8-x). *Reasoning:* D9 names a successor; 049 deleted because its old id was the *default* and a DELETE let the default change freely — here the successor is a fixed non-default row. `lastModel:cursor` in 064 → base id, exactly as 062.
