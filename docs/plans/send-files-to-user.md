## 1. Objective & success criteria

When a Claude Code agent calls `SendUserFile`, agetor must surface the delivered files as first-class UI instead of a collapsed generic tool card. Done means:

1. **Transcript card.** In the RunPanel stream, a `SendUserFile` tool_use renders a prominent "Files sent to you" card (replacing the generic `ToolUseBlock`, the way `PlanCard` does): the caption, then a wrapping **tile grid** (~96px tiles) — a real image preview (checkerboard behind transparency) for images, a large type icon otherwise, a **folder icon** when the path is a directory on disk — with filename and size beneath each tile, plus a status row (`N files delivered` / `Sending…` while no result / the tool's error text on `is_error`). **Historical transcripts render too** — the card derives from the persisted tool_use input, no reprocessing.
2. **Click to open.** Clicking a tile opens the path with the OS default app via `/open-path` (Finder for a directory). Hover shows the full path. A small secondary menu offers **Copy path** and **Reveal in Finder**. A path that no longer exists renders dimmed with an "ImageOff/FileWarning" glyph and clicking it opens the same not-found dialog `AttachmentChips` uses; any other open failure opens the "Couldn't open" dialog.
3. **Attachment metadata forwarded.** `claude-tmux` additively forwards Claude's structured `toolUseResult.attachments[{path,size,isImage,media_type}]` on the `tool_result` event (success only), so new transcripts keep size/type even after a temp file is gone.
4. **Task-level record + board badge + CLI.** The orchestrator detects a *delivered* `SendUserFile` (tool_result, not error) for any agent kind, persists a server-managed `tasks.sent_files` JSON list (migration 050; deduped by path; targeted UPDATE that does not bump `updated_at`; not PATCHable), exposes it as optional `Task.sentFiles`, renders a paperclip+count badge on the board `TaskCard` ("Total files sent, persistent"), and adds `agetor files <task>` to the CLI.
5. **Notification.** A new `GlobalEvent` kind `files-sent` drives a toast ("Claude sent you 2 files" with Open) whenever the task isn't the open panel or the window is unfocused, and a native macOS notification when the window is unfocused **or** the send was `status: "proactive"`.
6. **CLI/TUI parity.** `agetor logs` and the TUI dashboard print a `📎 sent N files: a.png (1.2 MB), b.md` line for the tool_use (shared formatter), instead of the bare `▸ SendUserFile`.
7. **Similar harnesses.** Codex, Cursor and Gemini have no send-to-user event (verified against their current docs) — nothing to build. fx speaks ACP, whose `ContentBlock` has a `resource_link` variant that fx 0.0.7 never emits: `mapFxUpdate` gets a **dormant, unit-tested mapping** from `file://` resource links inside a completed `tool_call`'s `content` to a synthetic `SendUserFile`-shaped tool_use + tool_result, so the same card, badge and CLI light up if fx ever sends one.
8. **Docs.** CLAUDE.md gains the new claude-derived surface (item **(5)** in the "claude-specific derived surfaces" bullet), the fx bullet notes the dormant mapping, and the stale PATCH allow-list sentence in numbered item 6 is corrected (owner pulled this in at the grill).
9. **Tests green.** Unit tests for every new module; an e2e spec (`e2e/sent-files.spec.ts`) drives the fake claude driver through a prompt marker and asserts the card, thumbnails, error card, badge and the headless open-failure dialog.

## 2. Context & constraints (grounded)

### Wire shapes — verified from 15 real transcripts (Claude Code 2.1.258–2.1.263) plus one live probe
- **tool_use input**: `{ files: string[], caption?: string, status: "normal" | "proactive", display?: "render" | "attach" }`. Paths were absolute in every observed call (scratchpad `/private/tmp/claude-501/…`, `~/Downloads/…`, `~/.maestro/…`); the tool description allows cwd-relative. `status` is real but appears only in the tool's own description, not Anthropic's tools-reference page.
- **Success tool_result** (`user` JSONL line): `content: "N file(s) delivered to user.\n  <path> → file_uuid: <uuid>\n  …"`, `is_error` absent. The same line carries a top-level **`toolUseResult` object** `{ caption, display, attachments: [{ path, size, isImage, media_type, pathValidated, file_uuid }] }`.
- **Error tool_result** (live probe, this session, 2.1.263): passing a directory → `is_error: true`, `content: "<tool_use_error>Attachment \"<path>\" is not a regular file.</tool_use_error>"`, and `toolUseResult` is a **string** (`"Error: Attachment … is not a regular file."`), not an object. **Directories are rejected** — so for Claude a folder can only appear on an errored call; the folder tile is stat-driven and mostly serves that error case and the ACP mapping.
- Known upstream bug (issues #76739/#88889/#90455): the success text is returned even when client-side delivery silently fails — agetor's "delivered" means "the tool reported delivery", nothing more.
- Availability: the tool exists only when a Remote Control client is connected or in a managed cloud session; agetor sessions on this machine do use it (14 calls in agetor worktree transcripts), so the feature is live-relevant.

## 3. Approach & key decisions

1. **One shared parser, three consumers** (`src/shared/sent-files.ts`) — same decision as tagged user messages (`user-message.ts`) and todo progress: webview card, CLI/TUI formatter and bun detection all import the one module, so "what counts as a sent file" can't drift. *Reasoning:* three surfaces already exist for tool events; a per-surface parser is how they drifted before.
2. **Rendering-only derivation for the card, additive metadata for richness** — the card needs only the tool_use input (works on every historical transcript); the forwarded `attachments` (D3 below) and the live `/refs/resolve` stat enrich it. *Alternative rejected:* deriving the card from a server-side table would leave old transcripts un-upgraded, exactly what the tagged-messages work avoided.
3. **`attachments` forwarding is shape-validated, not name-gated** — claude-tmux forwards `toolUseResult.attachments` whenever `toolUseResult` is an object whose `attachments` is an array of `{ path: string, … }` items, sanitized to `{ path, size?, isImage?, mediaType? }`. *Reasoning:* the driver doesn't track tool_use names per id; consumers key on the tool name anyway; AskUserQuestion's answer flow also carries `attachments` and forwarding them is harmless (nobody renders them yet). Errored results have a **string** `toolUseResult` and forward nothing.
4. **Result-gated detection with a DB fallback** — the orchestrator remembers `toolUseId → request` for `SendUserFile` tool_uses (per-run in-memory map, bounded) and acts on the matching non-error `tool_result`; if the map misses (agetor restarted mid-flight, reattach replay) and the result text matches `/files? delivered to user/`, it looks the tool_use up by id in `run_events` (`runs.findToolUseEvent(runId, toolUseId)`, `LIKE '%"id":"toolu_…"%'` prefilter + JSON confirm). Persisting on delivery, not on request, keeps the badge honest; `mergeSentFiles` dedupes by path so replays are idempotent. *Alternative rejected:* persisting at tool_use time (counts undelivered files).
5. **Dedicated targeted UPDATE for `sent_files`, excluded from the generic SET clause, no `updated_at` bump** — the unread-watermark pattern, not the todo_progress one. *Reasoning:* an unrelated PATCH must not clobber a concurrent send, and the board must not re-render every task on every poll; a real change still re-renders because the row JSON differs.
6. **`GlobalEvent` `files-sent`** rides the existing lifecycle channel; App.tsx decides toast vs native notification with the same `isSelected`/`isFocused` inputs the interaction toasts use, plus `proactive`. *Reasoning:* the channel exists and is live-only, which is right — a replayed historical send must not notify.
7. **Reveal in Finder = a new `native.revealPath`** implemented in `src/bun/index.ts` as `Bun.spawn(["open", "-R", abs])` (arm64 macOS is the only release target), exposed as `POST /reveal-path` with the same abs-or-task-relative + `existsSync` + 501-headless contract as `/open-path`. *Alternative rejected:* spawning `open -R` from the route without the `native` seam would make headless behave differently from `/open-path` and be untestable through `makeTestNative`.
8. **Tile model is a pure function** — `buildSentFileTiles(request, result, stats)` in `src/mainview/lib/sent-files-view.ts` merges input paths, forwarded attachments and stat results into `{ path, name, kind: "image"|"file"|"folder", exists, size, isError }` tiles; the component only renders. *Reasoning:* no jsdom in this repo — the logic that matters is unit-tested as a pure module, the rendering by Playwright.
9. **fx mapping is dormant by construction** — emitted only from a `completed` `tool_call_update` whose `content` carries `file://` `resource_link` blocks, synthetic ids `<toolCallId>:sent-files`, unit-tested against a fake update, documented as forward-compat like the existing `plan`/`usage_update` mappings. `display`/`status` default to `null`/`"normal"`.
10. **`display` is informational only** — image thumbnails always render (owner's requirement); `display: "attach"` shows a small "attachment" badge, `"render"` none. Not a question worth the owner's time; recorded as an assumption.
11. **Badge semantics** (owner): cumulative delivered-file count, deduped by path, persistent while > 0; tooltip lists the latest five basenames. Subagent (background-agent) transcripts never reach `makeChunkHandler`, so their sends render as cards in the subagent tab but don't count toward the badge — same boundary the todo tracker already has.

## 7. Blast radius & risks

- **`tool_result` event data grows** an optional `attachments` field for every claude tool whose `toolUseResult` carries one — consumers that `JSON.parse` the data already tolerate unknown keys (`safeParse<ParsedToolResult>`); `eventDedupKey` uses `data.slice(0,200)` for user events only. Low risk.
- **`Task` JSON grows** an optional `sentFiles` — fixtures unaffected (optional); board memo stability preserved (targeted UPDATE, no `updated_at` bump).
- **New migration 050** — additive nullable column; never edit once applied. Dogfood only against `~/.agetor-dev`.
- **`/files/preview` serves any absolute image path** — unchanged; sent files often live in `/private/tmp` scratchpads, which is why the card must handle `exists: false` gracefully after a reboot.
- **`open -R`** is macOS-only (project ships arm64 macOS only); headless returns 501 like `/open-path`.
- **Search/fold consistency** — the substituted card keeps `tool_result` ownership by `toolUseId`, so `findMatchingEventIds`' fold still lands matches on a rendered block.
- **Rollback** — revert the branch; the column stays (harmless nullable); no data migration.
- **Upstream drift** — if Claude Code renames the tool or changes the delivered text, the card degrades to the generic `ToolUseBlock` (rendering) and the badge stops counting (detection); nothing breaks.
