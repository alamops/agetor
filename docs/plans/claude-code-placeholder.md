## 1. Objective & success criteria

Two defects compound into the owner's symptom (a "Claude is asking something Agetor can't read" card on an idle task that then sits `running` for hours). Fix both, plus the three side surfaces the owner swept in.

1. **Placeholders read as an idle composer (B).** A live `❯` row whose only text is Claude's dim placeholder (prompt suggestion, startup `Try "…"` sample, `Message @<agent>…`) is **fully idle** for every caller: the stuck-turn watchdog never arms on it, the idle-settle net can close a turn that never wrote `end_turn`, and the paste / composer-clear paths treat the box as empty (never send `Escape Escape` into it).
2. **Suggestions off in agetor sessions.** Every claude-code launch (built-in and extra-account harnesses, fresh and `--resume`) carries `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`. No Settings toggle.
3. **No phantom continuation on compaction (A).** A `user` JSONL line carrying `isCompactSummary: true` or `isVisibleInTranscriptOnly: true` never adopts an `origin: "continuation"` run.
4. **Compaction renders honestly.** Every compaction (idle, mid-turn auto, manual `/compact`) shows a status line built from Claude's `compact_boundary` metadata, a collapsed "Compaction summary" block holding Claude's own summary text, and the `informational` notice as a status line — for **new events only** (ingest-side marker; stored rows keep rendering as before). The summary is never a YOU bubble, never offered for resend, never the first-load anchor, never marks the task unread, never moves a column. CLI/TUI print the status line plus one `summary›` line.
5. **Honest continuation wording.** `startContinuationRun` says what actually happened: `auto-continued after background task` (notification), `turn started from the terminal` (a `user` line typed in the attached terminal), `Claude continued on its own` (assistant-line trigger).

Done means: `bun run typecheck` green; `bun test` green except the three known pre-existing failures (tmux-socket ×2, reconcile cancel); the new unit suites in §5 pass; `e2e/compaction-summary.spec.ts` passes; the manual smoke (§5) on `~/.agetor-dev` shows a bare `❯` after boot and no card after a short turn; docs in §4/T8 updated. No schema change, no backfill, no feature flag.

## 3. Approach & key decisions

Owner decisions 1–10 and D1–D11 (grill) are taken as given. The calls below are the planner's; each is marked **evidence** or **reasoning**.

- **P1 — Second styled read, only when needed (D4, evidence + reasoning).** Every predicate keeps reading plain text. After a plain capture, when `livePromptRow(plain)` is non-bare, ONE extra `tmux capture-pane -p -e -t <session>` is taken through a new injectable `captureStyledTail(state): Promise<string | null>` (default: the `-e` capture sliced to the same last-40-line tail; `null` on failure; seam `__forTest.setCaptureStyledTail`). The styled row is located by the plain row's **raw line index** (`livePromptRowIndex(plainTail)` → index into `tail.split("\n")`; `livePromptRow` is re-expressed over it), and trusted only when `stripSgr(styledLine).trimEnd() === plainLine.trimEnd()` — a mismatch means the pane moved between the two reads and reads as "not a placeholder" (today's behaviour), never as idle. Fingerprints, matchers and the `__external__` sweep never see escape bytes, so #191's de-flicker is untouched. Cost: one extra tmux call per tick only while the row is non-bare, i.e. while a placeholder or stranded text is showing.
- **P2 — The placeholder rule (D3, evidence).** `isPlaceholderRow(styledRow)`: the plain projection must match `/^\s*❯\s+\S/` and must NOT match `/\[Pasted text/` or `/\[Image #\d+\]/` (explicit exclusions, although the spike shows both chips are plain-coloured anyway). Then walk the styled row with an SGR state machine over `ESC[…m` sequences — params split on `;`; empty/`0` resets dim+invert; `2` sets dim; `22` clears dim; `7` sets invert; `27` clears invert; every other param (colours `39`, etc.) ignored; a non-`m` CSI final is skipped. Characters before and including `❯` are skipped; whitespace (JS `\s`, so U+00A0 too) is skipped; every other character must be dim, except that the **first** visible character may be inverted instead of dim (the cursor block). At least one visible character is required. This accepts both observed shapes (contiguous span; per-word spans with `\x1b[0m` resets at the spaces) and both reset styles for the inverted first char (`\x1b[7mO\x1b[27m\x1b[2m…` and `\x1b[7mO\x1b[0m\x1b[2m…`), and rejects typed text, the chips, and a mixed row (`[Image #2] hello`).
- **P3 — Predicates gain an optional styled argument; "idle" means bare OR placeholder (decision 3).** `paneShowsIdleInputBox(tail, styledTail?: string | null)` = bare row, or (styled given and `placeholderRowShowing(tail, styledTail)`); `paneShowsComposerText(tail, styledTail?)` = `!working && non-bare && !placeholderRowShowing(...)`. Call sites pass the styled tail per D5: `scrapeOnce` (`paneIdle`), `queuePaste` (pre-clear check, post-clear positive verify, already-bare branch), `dismissAskModalForMessage` (both checks), `autoConfirmSlashModal` (idle early-exit). With no styled tail the predicates behave exactly as today, so every existing fixture keeps passing.
- **P4 — Summary carried as a NEW stream, `compaction_summary` (decision 5 + D7, reasoning).** `RunEventStream` gains `"compaction_summary"`; the mapper emits `onChunk("compaction_summary", <Claude's content verbatim, CR-normalised like a human turn>, uuid)` for a `user` line with `isCompactSummary === true`. Why a stream and not a tag or a `status`: the persisted `data` stays Claude's own text with no agetor-authored wrapper (grill constraint); `runs.lastUserEventId` and `runs.userMessageHistory` both filter `stream = 'user'`, so the first-load anchor and the resend picker exclude it **by construction** (D7) with zero query changes; `noteAssistantEvent` fires only for `assistant`, so the unread dot is untouched; `eventDedupKey`'s generic branch and `canonicalizeUserText` are untouched; a `status` divider cannot hold 16 KB and the CLI prints status lines whole. Rejected: a `<compaction_summary>` tag inside a `user` chunk (agetor-authored text in persisted data; `UserMessageBlock`, the history query and the anchor query would each need a filter); `status` (see above). Cost: four renderers gain a case (RunPanel, `agetor logs`, TUI, `searchableEventText`); `bun run typecheck` surfaces any exhaustive switch.
- **P5 — Two independent status lines, never joined (D7 ordering question, reasoning).** `compact_boundary` → `context compacted · 450k → 8.6k tokens` (`(manual)` inserted after "compacted" when `trigger === "manual"`; just `context compacted` when either token count is missing/non-numeric); `informational` whose `content` matches `/^compacted\b/i` → that content verbatim as its own status line (other `informational` notices stay dropped, as today — scope). Rationale: events are append-only and already broadcast, so a joined line would need a deferral timer that races the summary block's position and the 280 ms gap, while the owner's bar is legibility only; two lines in file order (boundary → block → notice) read fine, and a manual `/compact` simply has no second line.
- **P6 — Env var default, harness env may override (D2, reasoning).** `buildCommand`'s claude-code branch sets `env.CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION ??= "false"` right after `harnessEnv(harness)` — i.e. agetor supplies the default for every launch (built-in + extra-account, fresh + resume, since both go through `buildCommand`), but a harness whose own `env` map explicitly sets the var keeps its value. This is not a Settings toggle (nothing new in the UI); it is the existing per-harness env escape hatch, and it is what lets the live smoke exercise detection (§5) without a code change. The user's `promptSuggestionEnabled` setting is still overridden (env wins in the binary). Veto-able: if the owner wants agetor's value to win unconditionally, change `??=` to `=` in T2 and drop the "harness env wins" test in TT2.

"notification" : evt.type === "assistant" ? "assistant" : "user"`; `openContinuationRun(taskId, trigger = "notification")`; `startContinuationRun(taskId, trigger: ContinuationTrigger = "notification")` emits `CONTINUATION_STATUS_TEXT[trigger]`. The default keeps the fake driver / pipeline-handoff wording and the three existing assertions unchanged.

## 7. Blast radius & risks

- **`scrapeOnce` cost**: one additional `tmux capture-pane -p -e` per tick only while the live row is non-bare. Bounded; no change on a bare row. A styled capture failure degrades to today's reading (no idle), never to a false idle.
- **TOCTOU between the two captures**: mitigated by the plain-projection equality check (P1); a mismatch is treated as "text present".
- **Idle-settle now closes placeholder-bearing turns** (decision 3). Intended; it is the same trade the net already makes for a bare row. A genuinely wedged turn whose pane shows a suggestion is settled (`succeeded`, → `review`) instead of carded.
- **Env var**: fresh/resume launches of every claude-code harness lose prompt suggestions (owner decision); a harness env override restores them (P6). Reattached pre-upgrade sessions keep suggestions until they respawn — detection covers them.
- **`RunEventStream` union growth**: every exhaustive `switch` over it must gain a case — typecheck finds them; the webview `default` → `RawText` is only a fallback. Older CLI/TUI builds talking to a newer core would print a `compaction_summary` event through their own `default` branch (raw text) — acceptable, same version-skew posture as every prior stream addition.
- **Rebuild from JSONL** re-emits historical compactions in the new shape (P9) — a visible change only when a user clicks "Rebuild", never on the stored rows themselves.
- **Continuation factory signature**: optional second param keeps every existing one-arg caller/test compiling; the three wording assertions (`orchestrator-continuation.test.ts:213`, `pipeline-runner.test.ts:1711`, `e2e/pipelines-run.spec.ts:770`) are on the notification/default path and stay green.
- **Sessions already alive at upgrade**: no migration; a phantom run already open before the upgrade settles via the new idle-settle behaviour on the next tick (~66 s) once the process restarts and reattaches.
- Rollback: revert the branch; no data migration to undo (`compaction_summary` rows left in `run_events` would render through the old webview's `default` branch as raw text).

- Enter on an empty composer showing a suggestion is a no-op (changelog 2.1.136) — only relevant to sessions reattached across the upgrade; low exposure, not live-verified.
